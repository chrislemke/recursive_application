# OpenAI provider and ChatGPT-subscription (Codex sign-in) library and protocol facts (2026-09-06)

Research against primary sources only: the installed package source under `.venv/lib/python3.12/site-packages/` (abbreviated `SP/`; every path is relative to it unless it starts with `/`), the openai/codex GitHub repository at tag `rust-v0.153.4` (matching the installed `codex-cli 0.153.4`; tree sha `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a`; files fetched from `raw.githubusercontent.com` on 2026-09-06 and cited as `codex-rs/<path>:<lines>` or `docs/<file>`, `sdk/<file>`), OpenAI's Codex documentation (fetched from `learn.chatgpt.com/docs/*`, each page with a `.md` twin, on 2026-09-06; the repo's `docs/authentication.md` links to `developers.openai.com/codex/auth`, and the fetched pages carry `learn.chatgpt.com` canonical URLs, so the two hosts are treated as the same documentation set here), the local `codex --help` output and `codex login status`, and probe scripts run offline with `uv run --no-sync python` from the repo root against `httpx.MockTransport`/`httpx2.MockTransport` only. Hard rules were kept: `~/.codex/auth.json` was never opened (its schema comes from the Rust source), and no request went to any OpenAI, ChatGPT or OpenRouter endpoint. Where a source could not be reached (OpenAI Terms of Use, Usage Policies and help-center articles returned HTTP 403/Cloudflare challenges to every fetch) the section says so instead of guessing. Summary: Codex stores `$CODEX_HOME/auth.json` (default `~/.codex/auth.json`, mode 0600 on create, plain truncate-and-write, no lock) with `auth_mode`, `OPENAI_API_KEY`, `tokens.{id_token,access_token,refresh_token,account_id}` and `last_refresh`; `account_id` is the `https://api.openai.com/auth.chatgpt_account_id` claim of the id token. It refreshes at `POST https://auth.openai.com/oauth/token` with JSON `{client_id: "app_EMoamEEZ73f0CkXaXp7hrann", grant_type: "refresh_token", refresh_token}` when the access-token JWT `exp` is within 5 minutes or `last_refresh` is older than 8 days, and once more after a 401; the response rotates the refresh token, which Codex writes back, and a reused refresh token is a permanent failure. The model call is `POST https://chatgpt.com/backend-api/codex/responses` with `Authorization: Bearer`, `ChatGPT-Account-ID`, `originator`, `User-Agent`, `session-id`/`thread-id`, `Accept: text/event-stream` and a body that always has `stream: true`, `store: false`, `include: ["reasoning.encrypted_content"]`, `reasoning`, `prompt_cache_key` and never `max_output_tokens`/`previous_response_id`; Codex has no non-streaming client, so whether the backend accepts `stream: false` is unverified. 429s arrive as `error.type: "usage_limit_reached"` with `x-codex-primary-used-percent`/`-reset-at` style headers and are not retried by Codex; 401s trigger reload-then-refresh-then-retry. Models come from `GET .../codex/models?client_version=…` cached in `models_cache.json` (TTL 300 s); the default is the highest-priority listed model, `gpt-6-astra` on this machine. OpenAI's docs call API keys "the right way to authenticate automation", describe the supported way to keep a ChatGPT session alive as "run Codex and persist the updated `auth.json`" ("not 'call the refresh API yourself'"), and scope that guidance to Codex, excluding "generic OAuth clients outside Codex"; no sentence explicitly permits or forbids reusing the tokens from another client. On the Python side, openai 3.8.0 runs on `httpx2` (legacy `httpx` accepted with a pydantic-ai deprecation warning), accepts a callable `api_key` re-evaluated before every request, and `OpenAIProvider(base_url=…)` plus an `AsyncBaseTransport` that rewrites `stream:false` to `stream:true` and folds the `response.completed` event into a JSON body works end-to-end through `Agent.run_sync` (probe), yielding `ModelHTTPError(status_code=401)` for expired tokens and list-price `cost` for model ids genai-prices 0.1.6 knows (not `gpt-6-astra`, `gpt-5.4-codex`).

## A. Codex CLI 0.153.4 "Sign in with ChatGPT" (openai/codex, tag rust-v0.153.4)

### A1. The auth file

- Location: `find_codex_home()` honours `CODEX_HOME` ("the value must exist and be a directory", canonicalised; errors "CODEX_HOME points to … but that path does not exist / is not a directory") and otherwise uses `dirs::home_dir()` + `.codex`. The file is `codex_home.join("auth.json")`. Source: `codex-rs/utils/home-dir/src/lib.rs:6-59`; `codex-rs/login/src/auth/storage.rs:154-156`.
- Schema (serde struct `AuthDotJson`, "Expected structure for $CODEX_HOME/auth.json"), verbatim field list:

  ```rust
  pub struct AuthDotJson {
      #[serde(default, skip_serializing_if = "Option::is_none")] pub auth_mode: Option<AuthMode>,
      #[serde(rename = "OPENAI_API_KEY")]                        pub openai_api_key: Option<String>,
      #[serde(default, skip_serializing_if = "Option::is_none")] pub tokens: Option<TokenData>,
      #[serde(default, skip_serializing_if = "Option::is_none")] pub last_refresh: Option<DateTime<Utc>>,
      #[serde(default, skip_serializing_if = "Option::is_none")] pub agent_identity: Option<AgentIdentityStorage>,
      #[serde(default, skip_serializing_if = "Option::is_none")] pub personal_access_token: Option<String>,
      #[serde(default, skip_serializing_if = "Option::is_none")] pub bedrock_api_key: Option<BedrockApiKeyAuth>,
      #[serde(default, skip_serializing_if = "Option::is_none")] pub bedrock_access_keys: Option<BedrockAccessKeysAuth>,
  }
  ```
  So every key except `OPENAI_API_KEY` is optional and omitted when `None`; `OPENAI_API_KEY` is always written (as `null` for a ChatGPT login) and `auth_mode` may be absent in files written by older versions. Source: `codex-rs/login/src/auth/storage.rs:39-66`.
- `tokens` (`TokenData`): `id_token` (a JWT string on disk; deserialised into `IdTokenInfo` by `deserialize_id_token`, re-serialised from `raw_jwt`), `access_token: String` ("This is a JWT."), `refresh_token: String`, `account_id: Option<String>`. `last_refresh` is an RFC 3339 UTC timestamp (`DateTime<Utc>`). Source: `codex-rs/login/src/token_data.rs:11-25, 160-175`.
- JWT claims Codex reads (`IdClaims`): top-level `email`, `https://api.openai.com/profile` → `email`, `https://api.openai.com/auth` → `chatgpt_plan_type`, `chatgpt_user_id` (fallback `user_id`), `chatgpt_account_id`, `chatgpt_account_is_fedramp`; standard `exp` via `parse_jwt_expiration`. Plan types recognised: `free`, `go`, `plus`, `pro`, `prolite`, `team`, … Source: `codex-rs/login/src/token_data.rs:70-106, 130-160`; `codex-rs/protocol/src/auth.rs:76-81`.
- How `account_id` is obtained: at login completion `tokens.account_id = jwt_auth_claims(&id_token).get("chatgpt_account_id")`, i.e. the **id token's** `https://api.openai.com/auth.chatgpt_account_id` claim; consumers fall back to `token_data.id_token.chatgpt_account_id` when the stored field is empty, and a forced workspace id from config wins over both. Source: `codex-rs/login/src/server.rs:895-908`; `codex-rs/login/src/auth/manager.rs:840-848, 584-597`.
- `AuthMode` values and their JSON spelling (`#[serde(rename_all = "lowercase")]` plus explicit renames): `apikey`, `chatgpt` ("ChatGPT OAuth managed by Codex (tokens persisted and refreshed by Codex)"), `chatgptAuthTokens` ("supplied by an external host application"), `headers`, `agentIdentity`, `personalAccessToken`, `bedrockApiKey`, `bedrockAccessKeys`. `has_chatgpt_account()` is true for `Chatgpt | ChatgptAuthTokens | PersonalAccessToken`. Source: `codex-rs/protocol/src/auth.rs:7-49`.
- File permissions on write (`FileAuthStorage::save`): `create_dir_all(parent)`, `serde_json::to_string_pretty`, then `OpenOptions::new().truncate(true).write(true).create(true)` with `#[cfg(unix)] options.mode(0o600)`, `write_all`, `flush`. **Not atomic**: no temp file, no rename, no file lock; `mode(0o600)` only applies when the file is created, an existing file keeps its mode. Load is a plain `File::open` + `serde_json::from_str`. Source: `codex-rs/login/src/auth/storage.rs:183-222`.
- Alternative storage: config `cli_auth_credentials_store` = `file` (default, "Persist credentials in CODEX_HOME/auth.json"), `keyring` ("Fail if unavailable"), `auto` ("Use keyring when available; otherwise, fall back to a file in CODEX_HOME"), `ephemeral` ("in memory only"). Keyring entries use service `"Codex Auth"`, secret name `CODEX_AUTH`, key = SHA-256 of the canonical `codex_home` path. Source: `codex-rs/config/src/types.rs:107-121`; `codex-rs/config/src/config_toml.rs:264`; `codex-rs/login/src/auth/storage.rs:246-262`. The CI/CD doc adds: "If your credentials are stored in the OS keyring, switch to file-backed storage first." (`learn.chatgpt.com/docs/auth/ci-cd-auth`, accessed 2026-09-06).
- Environment variables: constants `OPENAI_API_KEY_ENV_VAR = "OPENAI_API_KEY"`, `CODEX_API_KEY_ENV_VAR = "CODEX_API_KEY"`, `CODEX_ACCESS_TOKEN_ENV_VAR = "CODEX_ACCESS_TOKEN"` with trimmed, non-empty readers; `load_auth` consults `CODEX_ACCESS_TOKEN` (agent-identity / personal-access-token modes) and `from_auth_storage` passes `enable_codex_api_key_env = false`. Docs: "You can use `CODEX_API_KEY` with `codex exec`, `codex review`, the TypeScript SDK, and `codex exec-server --remote`." Source: `codex-rs/login/src/auth/manager.rs:411-431, 910-925, 1493-1500`; `learn.chatgpt.com/docs/non-interactive-mode` lines 142-154 (accessed 2026-09-06). Not verified: the exact precedence of `OPENAI_API_KEY` in the environment over a ChatGPT `auth.json` (the ordering inside `load_auth`, `manager.rs:1445-1550`, was not traced).

### A2. Token refresh

- Endpoint and client id: `REFRESH_TOKEN_URL = "https://auth.openai.com/oauth/token"`; `CLIENT_ID = "app_EMoamEEZ73f0CkXaXp7hrann"` ("Shared constant for token refresh (client id used for oauth token refresh flow)"), overridable with env `CODEX_APP_SERVER_LOGIN_CLIENT_ID`. Source: `codex-rs/login/src/auth/manager.rs:197, 201, 1708-1720`.
- Request (`request_chatgpt_token_refresh`): `POST` with `Content-Type: application/json` and JSON body `RefreshRequest { client_id: oauth_client_id(), grant_type: "refresh_token", refresh_token }` — three fields, no `scope`. Response `RefreshResponse { id_token: Option<String>, access_token: Option<String>, refresh_token: Option<String> }`. Source: `codex-rs/login/src/auth/manager.rs:1581-1612, 1694-1705`.
- Rotation and write-back (`persist_tokens`): re-loads the stored auth, replaces `id_token` (re-parsed), `access_token` and `refresh_token` **whenever the response contains them**, sets `last_refresh = Utc::now()`, and calls `storage.save(...)` (the non-atomic write above), then `self.reload()`. The tests stub the authority with `{"access_token":"new-access-token","refresh_token":"new-refresh-token"}` and assert the new refresh token is stored, so rotation is the expected server behaviour. Source: `codex-rs/login/src/auth/manager.rs:1555-1578, 3012-3025`; `codex-rs/login/tests/suite/auth_refresh.rs:63, 185-245`.
- Failure classification: HTTP 401, or HTTP 400 with `error.code == "invalid_grant"`, or a recognised reason → `RefreshTokenError::Permanent`; messages include "Your access token could not be refreshed because your refresh token has expired / **was already used** / was revoked. Please log out and sign in again." Anything else is `Transient`. Source: `codex-rs/login/src/auth/manager.rs:191-196, 1613-1632`.
- When Codex refreshes (proactive): `should_refresh_proactively` — for `AuthMode::Chatgpt` only, if the access token JWT has `exp`, refresh when `exp <= now + CHATGPT_ACCESS_TOKEN_REFRESH_WINDOW_MINUTES` (= 5); otherwise when `last_refresh < now - TOKEN_REFRESH_INTERVAL` (= 8 days). It runs inside `AuthManager::auth()`, i.e. every time the client fetches credentials for a request. Source: `codex-rs/login/src/auth/manager.rs:188-189, 2344-2356, 2924-2946`.
- When Codex refreshes (reactive, on 401): `UnauthorizedRecovery` is "a state machine that handles an attempt to refresh the authentication when requests to API fail with 401 status code. The client calls next() every time it encounters a 401 error, one time per retry. For API key based authentication, we don't do anything … For ChatGPT based authentication, we: 1. Attempt to reload the auth data from disk. We only reload if the account id matches the one the current process is running as. 2. Attempt to refresh the token using OAuth token refresh flow. If after both steps the server still responds with 401 we let the error bubble to the user." Wired from `TransportError::Http { status: 401 }` through `ProviderUnauthorizedRecovery` into `handle_unauthorized`. Source: `codex-rs/login/src/auth/manager.rs:1818-1900`; `codex-rs/model-provider/src/provider.rs:88, 198-211`; `codex-rs/core/src/client.rs:2314-2495`.
- Concurrency: `refresh_token()` takes a `refresh_lock` semaphore, then does a **guarded reload** (`reload_if_account_id_matches`): it re-reads `auth.json`, skips if the account id differs, and if the on-disk tokens differ from the cached ones it logs "Skipping token refresh because auth changed after guarded reload." and adopts the file's tokens instead of calling the authority. Only when the file is unchanged does it call `refresh_token_from_authority_impl` → `refresh_and_persist_chatgpt_token(refresh_token from the cached TokenData)`. There is no cross-process lock. Source: `codex-rs/login/src/auth/manager.rs:2768-2800, 2431-2465, 2830-2850`.
- Access-token lifetime: not a constant in the source; it is read from the JWT `exp` claim (`parse_jwt_expiration`). Not verified: the actual lifetime the authority issues.
- Login flows (for completeness): issuer `https://auth.openai.com`, local callback server on port 1455 with `redirect_uri = http://localhost:{port}/auth/callback`, authorize URL `{issuer}/oauth/authorize?client_id=…&redirect_uri=…&scope=…&code_challenge=…&code_challenge_method=S256&id_token_add_organizations=true&codex_cli_simplified_flow=true&originator=…`, token exchange `POST {issuer}/oauth/token` form-encoded `grant_type=authorization_code&code=…&redirect_uri=…&client_id=…&code_verifier=…`. Device-code flow: `{auth_base_url}/deviceauth/usercode`, `/deviceauth/token`, verification page `{base_url}/codex/device`, 15-minute timeout (`codex login --device-auth`). Source: `codex-rs/login/src/server.rs:59-60, 176, 578-611, 811-845`; `codex-rs/login/src/device_code_auth.rs:68, 107, 134, 174, 202`. (The `scope` value sits at `server.rs:589-593` and was not extracted.)

### A3. The model request on the subscription path

- Base URL and path: `CHATGPT_CODEX_BASE_URL = "https://chatgpt.com/backend-api/codex"`; `ModelProviderInfo::to_api_provider` uses it whenever the auth mode is `Chatgpt | ChatgptAuthTokens | Headers | AgentIdentity | PersonalAccessToken` and `https://api.openai.com/v1` otherwise (an explicit provider `base_url` overrides both). `supports_codex_backend_routes()` requires the OpenAI provider with a base URL ending in `/backend-api/codex`. The Responses path is `"/responses"` (`ResponsesEndpoint::Responses`; also `/guardian`, `/guardian-classifier`), joined by `Provider::url_for_path`, so the request is `POST https://chatgpt.com/backend-api/codex/responses`. Only `wire_api = "responses"` exists (`chat` was removed). Source: `codex-rs/model-provider-info/src/lib.rs:40, 58-68, 293-311, 472-479`; `codex-rs/codex-api/src/endpoint/responses.rs:40-46`; `codex-rs/codex-api/src/provider.rs:53-75`.
- Headers Codex sets (all verified in source):
  - `Authorization: Bearer <access_token>`, `ChatGPT-Account-ID: <account_id>`, and `X-OpenAI-Fedramp: true` for FedRAMP accounts — `BearerAuthProvider::add_auth_headers`, applied per request through the `AuthProvider` trait. Source: `codex-rs/model-provider/src/bearer_auth_provider.rs:31-46`; `codex-rs/codex-api/src/auth.rs:30-70`.
  - `originator: codex_cli_rs` (`DEFAULT_ORIGINATOR`; override env `CODEX_INTERNAL_ORIGINATOR_OVERRIDE`; `codex-tui`, `codex_vscode`, `Codex *`, `codex_atlas`, `codex_chatgpt_desktop` are the other first-party values) and `User-Agent: {originator}/{CARGO_PKG_VERSION} ({os_type} {os_version}; {arch}) {terminal user agent}` (optional suffix), plus optional `x-openai-internal-codex-residency: us`. Source: `codex-rs/login/src/auth/default_client.rs:40-42, 153-190, 335-350`.
  - `session-id` and `thread-id` (`build_session_headers`), `x-codex-installation-id`, `x-codex-window-id`, `x-codex-turn-metadata` (JSON), `x-codex-parent-thread-id`, `x-codex-routing-hint`, `x-codex-beta-features` (when configured), `x-codex-turn-state` (replays the token from the previous response's `x-codex-turn-state` header for sticky routing), `x-oai-attestation` (when available), `x-openai-subagent: review|compact`, `x-openai-memgen-request: true` (memory consolidation), `x-responsesapi-include-timing-metrics: true` (opt-in). Source: `codex-rs/codex-api/src/requests/headers.rs:5-24`; `codex-rs/core/src/client.rs:152-170, 309-328, 680-705, 2109-2127`; `codex-rs/core/src/responses_metadata.rs:342-362`; `codex-rs/core/src/attestation.rs:7`.
  - `Accept: text/event-stream` on the SSE request; optional zstd request compression. Source: `codex-rs/codex-api/src/endpoint/responses.rs:156-182`.
  - `OpenAI-Beta: responses_websockets=2026-02-06` is set on the **WebSocket** connect path; no `OpenAI-Beta` header was found on the HTTP SSE path. Source: `codex-rs/core/src/client.rs:152, 166, 1259-1262`.
- Body: the serialised struct is `ResponsesApiRequest { model, instructions (skipped if empty), input, tools (skipped if None), tool_choice, parallel_tool_calls, reasoning, store, stream, stream_options (opt), include, service_tier (opt), prompt_cache_key (opt), text (opt), client_metadata (opt), access_programs (opt) }` and Codex fills it as `tool_choice: "auto"`, `reasoning: Some({effort, summary})`, **`store: false`**, **`stream: true`**, **`include: ["reasoning.encrypted_content"]`**, `prompt_cache_key: Some(session-derived key)`, `text` = verbosity and/or output-schema format, `client_metadata: Some(turn ids)`, `access_programs: None`. The struct has **no** `max_output_tokens`, `previous_response_id` (the WebSocket variant carries `previous_response_id: None`), `truncation`, `metadata`, `safety_identifier`, `user`, `temperature`, `top_p`. Source: `codex-rs/codex-api/src/common.rs:275-300, 336-349`; `codex-rs/core/src/client.rs:985-1030`.
- Streaming is the only implemented mode: `ResponsesClient` exposes `stream_request`/`stream` (SSE) and `codex-api/src/endpoint/responses_websocket.rs` the WebSocket variant; there is no unary Responses call and the body is hard-coded `stream: true`. **Not verified (offline research): whether `https://chatgpt.com/backend-api/codex/responses` accepts `stream: false`.** Source: `codex-rs/codex-api/src/endpoint/responses.rs:93-190`.
- Retry policy on this path: `ApiRetryConfig { max_attempts: request_max_retries() (default 4, cap 100), base_delay: 200 ms, retry_429: false, retry_5xx: true, retry_transport: true }`; backoff `base * 2^(attempt-1)` with jitter 0.9–1.1; stream reconnects `stream_max_retries` (default 5), stream idle timeout 300 s, websocket connect timeout 15 s; the stream-retry loop uses connection delays 5 s → 60 s. Source: `codex-rs/model-provider-info/src/lib.rs:27-35, 313-319, 359-383`; `codex-rs/codex-client/src/retry.rs:22-47`; `codex-rs/core/src/responses_retry.rs:17-18`.
- Error surfacing:
  - HTTP 401 → `TransportError::Http { status: 401 }` → the reload/refresh/retry sequence in A2, then the error bubbles.
  - HTTP 429 → body parsed as `UsageErrorResponse`; `error.type == "usage_limit_reached"` becomes `CodexErr::UsageLimitReached { plan_type, resets_at (unix seconds from `error.resets_at`), rate_limits, promo_message, rate_limit_reached_type }`, `"usage_not_included"` → `UsageNotIncluded`; the limit family is chosen by header `x-codex-active-limit`. Not retried (see `retry_429: false`). Source: `codex-rs/codex-api/src/api_bridge.rs:133-160, 199`.
  - Rate-limit headers parsed (`parse_rate_limit_for_limit`, prefix `x-<limit-id>` with default limit id `codex`): `x-codex-primary-used-percent`, `x-codex-primary-window-minutes`, `x-codex-primary-reset-at`, `x-codex-secondary-used-percent`, `x-codex-secondary-window-minutes`, `x-codex-secondary-reset-at`, `x-codex-credits-has-credits`, `x-codex-credits-unlimited`, `x-codex-credits-balance`, `x-codex-promo-message`, `x-codex-rate-limit-reached-type`, plus any other `x-<id>-primary-used-percent` family (e.g. `codex_other`). They are read from **every** SSE response's headers and emitted as `ResponseEvent::RateLimits`. Other response headers read: `X-Models-Etag`, the `openai-model` header, a request-id header, `X-Reasoning-Included`. Source: `codex-rs/codex-api/src/rate_limits.rs:23-100, 179-230, 261-266`; `codex-rs/codex-api/src/sse/responses.rs:36-80`.
  - In-stream failures: `response.failed` with `error.code` `rate_limit_exceeded` → `ApiError::RateLimitExceeded { message, delay parsed from "try again in Ns" }`, `insufficient_quota` → `QuotaExceeded`, `usage_not_included`, context-window errors, `invalid_prompt`/`bio_policy` → `InvalidRequest`, server-overloaded → `ServerOverloaded`. Source: `codex-rs/codex-api/src/sse/responses.rs:413-461, 677-712`; `codex-rs/codex-api/src/error.rs:9-45`.
  - Usage delivery: the `response.completed` event → `ResponseEvent::Completed { response_id, token_usage: response.usage, usage_metadata, end_turn }`; there is no per-request cost in the HTTP protocol. Source: `codex-rs/codex-api/src/sse/responses.rs:479-497`.

### A4. Model ids on the ChatGPT path

- List endpoint: `GET {base_url}/models?client_version=<major.minor.patch>` with an `ETag`/`If-None-Match` round trip — on the subscription path `https://chatgpt.com/backend-api/codex/models?client_version=0.153.4` (test fixture: `https://example.com/api/codex/models?client_version=0.99.0`). Source: `codex-rs/codex-api/src/endpoint/models.rs:31-78, 191`.
- Cache: `MODEL_CACHE_FILE = "models_cache.json"` under `CODEX_HOME`, `DEFAULT_MODEL_CACHE_TTL = 300 s`; entry `{fetched_at, etag, client_version, models}`; a cached entry is used only if `client_version` matches and it is fresh; refresh strategies `Offline` / `OnlineIfUncached` / `Online`. Source: `codex-rs/models-manager/src/manager.rs:28-30, 380-430`; `codex-rs/models-manager/src/cache.rs:63-91, 170-200`. Local check (keys only, no secrets): `~/.codex/models_cache.json` has `fetched_at: 2026-09-06T08:18:49Z`, `client_version: "0.153.4"`, 8 models.
- Source of truth (`apply_remote_models`): "Use the remote models list as the source of truth if it contains at least one non-hidden model and the user is using ChatGPT auth." Otherwise the remote list is merged into the bundled `models.json` (11 entries, compiled in with `include_str!`). ### B6. Error mapping and SDK retries

- pydantic-ai: `_map_api_errors` wraps every Responses/Chat SDK call; an `openai.APIStatusError` with `status_code >= 400` becomes `ModelHTTPError(status_code=..., model_name=..., body=e.body, headers=dict(e.response.headers), suggested_model_id=...)`, an `APIConnectionError` becomes `ModelAPIError`. - openai 3.8.0 maps status codes to subclasses of `APIStatusError` (`status_code` attribute): 400 `BadRequestError`, 401 `AuthenticationError`, 403 `PermissionDeniedError`, 404 `NotFoundError`, 409 `ConflictError`, 422 `UnprocessableEntityError`, 429 `RateLimitError`, >=500 `InternalServerError`. - Retry defaults: `DEFAULT_MAX_RETRIES = 2`, `INITIAL_RETRY_DELAY = 0.5`, `MAX_RETRY_DELAY = 8.0`, `MAX_RETRY_AFTER_DELAY = 120`, `DEFAULT_TIMEOUT = Timeout(600, connect=5.0)`. `_should_retry` honours `x-should-retry: true|false`, then retries 408, 409, 429 and any >=500; everything else (401, 403, 400) is **not** retried. ### B8. SSE-to-JSON viability in openai 3.8.0

- `ResponseCompletedEvent` has `response: Response`, `sequence_number: int`, `type: Literal['response.completed']`, and `Response` carries `output: List[ResponseOutputItem]` and `usage: Optional[ResponseUsage]` (`input_tokens`, `output_tokens`, `total_tokens`, `input_tokens_details.cached_tokens/cache_write_tokens`, `output_tokens_details.reasoning_tokens`). Source: `SP/openai/types/responses/response_completed_event.py:11-20`; `SP/openai/types/responses/response.py:203-246, 469`; `SP/openai/types/responses/response_usage.py:8-46`.
- SSE parsing (`SP/openai/_streaming.py`): `AsyncStream.__stream__` iterates `SSEDecoder().aiter_bytes(response.aiter_bytes())` (`:162-164`), breaks on a `data:` line starting with `[DONE]` (`:174-175`), raises `APIError` when a JSON payload has an `error` key (`:197-210`), and otherwise yields `process_data(data=sse.json(), cast_to=ResponseStreamEvent)` (`:212-216`). `SSEDecoder.decode` implements the WHATWG rules: `event:`, `data:` (multi-line joined with `\n`), `id:`, `retry:`; a leading space after the colon is stripped; a `:`-prefixed comment line is ignored; an empty line dispatches the event (`:368-412`). The Responses API therefore needs no `[DONE]` sentinel, the stream simply ends after `response.completed`.
- Non-streaming `responses.create(...)` is `self._post('/responses', body=..., cast_to=Response, stream=stream or False, stream_cls=AsyncStream[ResponseStreamEvent])` (`SP/openai/resources/responses/responses.py:1056-1073`). Parsing (`SP/openai/_response.py:243-270`): the `content-type` must end with `json`; if not, a `BaseModel` cast still tries `response.json()`, and only `_strict_response_validation=True` raises `APIResponseValidationError` "Expected Content-Type response header to be `application/json`". So the adapter must return a JSON body of the `Response` object; `content-type: application/json` is what `httpx.Response(json=...)` sets.
- Probe `probe_b8_sse_adapter.py` (kept in the scratchpad; run with `uv run --no-sync python`, no network). The adapter that worked, verbatim:

  ```python
  def make_adapter(mod, inner):
      """Adapter transport: mod is httpx or httpx2, inner is a transport of the same family."""
      class SseToJsonTransport(mod.AsyncBaseTransport):
          async def handle_async_request(self, request):
              raw = await request.aread()  # request.content is only available after read
              try:
                  body = json.loads(raw) if raw else None
              except ValueError:
                  body = None
              if not isinstance(body, dict) or body.get('stream') is True:
                  return await inner.handle_async_request(request)  # streaming or non-JSON: pass through
              body['stream'] = True
              headers = mod.Headers(request.headers)
              for h in ('content-length', 'transfer-encoding'):
                  headers.pop(h, None)  # let Request recompute Content-Length for the new body
              headers['accept'] = 'text/event-stream'
              new_request = mod.Request(request.method, request.url, headers=headers,
                                        content=json.dumps(body).encode(), extensions=request.extensions)
              response = await inner.handle_async_request(new_request)
              await response.aread()
              if response.status_code != 200:
                  return response  # pass errors through untouched (401/429 keep their headers)
              completed = None
              for sse in SSEDecoder().iter_bytes(iter([response.content])):
                  data = sse.json()
                  if isinstance(data, dict) and data.get('type') == 'response.completed':
                      completed = data['response']
                  elif isinstance(data, dict) and data.get('type') in ('response.failed', 'error'):
                      return mod.Response(502, json={'error': data}, request=request)
              if completed is None:
                  return mod.Response(502, json={'error': {'message': 'stream ended without response.completed'}}, request=request)
              return mod.Response(200, json=completed, headers={'x-adapter': 'sse-to-json'}, request=request)
          async def aclose(self):
              await inner.aclose()
      return SseToJsonTransport()
  ```
  where `SSEDecoder` is `openai._streaming.SSEDecoder`, `mod` is `httpx` or `httpx2`, and `inner` is a `mod.MockTransport(handler)` whose handler returns `mod.Response(200, content=<sse bytes>, headers={'content-type': 'text/event-stream'})` for `stream: true` bodies and `400` otherwise. Client construction: `AsyncOpenAI(http_client=mod.AsyncClient(transport=make_adapter(mod, inner)), api_key='x', base_url='http://test/backend-api/codex')` then `await oai.responses.create(model='gpt-5.4', input='hi', instructions='x', store=False)`.

### B9. httpx 0.28.1 (and httpx2 2.12.0) facts for the adapter

- `class AsyncBaseTransport: async def handle_async_request(self, request: Request) -> Response` plus `async def aclose(self)` and `__aenter__/__aexit__`. Source: `SP/httpx/_transports/base.py:65-86`; httpx2 identical at `SP/httpx2/_transports/base.py:64-83`.
- Reading a request body: `request.content` raises `RequestNotRead` until the stream has been read; `await request.aread()` joins the async stream, caches `_content` and replaces the stream with a replayable `ByteStream`. Source: `SP/httpx/_models.py:462-494`. (The SDK builds requests with `content=`/`json=`, which are `ByteStream`s and already read, but `aread()` is the safe call either way.)
- Building a replacement: `httpx.Request(method, url, *, params=None, headers=None, cookies=None, content=None, data=None, files=None, json=None, stream=None, extensions=None)`; with `content=`/`json=`, `encode_request` computes `Content-Length`/`Content-Type` and `_prepare` only `setdefault`s them, so a stale `Content-Length` copied from the original headers would win, hence the adapter deletes `content-length`/`transfer-encoding` before constructing (`Host` is also auto-added when absent). Source: `SP/httpx/_models.py:382-460`; httpx2 `SP/httpx2/_models.py:397-415`.
- Returning a response from a transport: `httpx.Response(status_code, *, headers=None, content=None, text=None, html=None, json=None, stream=None, request=None, extensions=None, history=None, default_encoding='utf-8')`; `json=` serialises and sets `content-type: application/json` and `content-length`; `content=bytes` sets only `content-length`, so add `content-type` yourself (as the SSE mock does). Source: `SP/httpx/_models.py:515-570`; httpx2 `SP/httpx2/_models.py:525-540`.
- `MockTransport(handler)` accepts a sync or async handler `Callable[[Request], Response | Awaitable[Response]]`, calls `await request.aread()` first, and awaits the result if it is not already a `Response`. Source: `SP/httpx/_transports/mock.py:15-43`; httpx2 `SP/httpx2/_transports/mock.py:15-40`.
- Event hooks: `EventHook = typing.Callable[..., typing.Any]` (`SP/httpx/_client.py:185`); `AsyncClient._send_handling_redirects` does `for hook in self._event_hooks["request"]: await hook(request)` before `_send_single_request` and awaits response hooks after (`:1691-1697`), so on the async client hooks **must be awaitable** (the sync `Client` calls `hook(request)`, `:976-981`); they receive the live `Request` and may mutate `request.headers`. Verified by the probe: a hook setting `request.headers['chatgpt-account-id'] = 'acct-from-hook'` was visible at the inner transport. httpx2 has the same semantics (`SP/httpx2/_client.py:176, 1879-1884`). Hooks run per HTTP attempt, so they also run on SDK retries.
- Practical note: the openai SDK computes `Authorization` itself from `api_key` on each attempt (`_build_headers`, `SP/openai/_base_client.py:473-476`), so a request hook that overwrites `Authorization` and a callable `api_key` are two working ways to inject a freshly refreshed bearer per request; the callable is typed and needs no hook.

### B10. `Agent.override(...)` and `run_sync(model=...)`

- `Agent.override(*, name, deps, model, toolsets, tools, native_tools, instructions, metadata, model_settings, retries, spec)` is a context manager; a `model` override goes through `models.infer_model(model)` (a `Model` instance is returned unchanged, `SP/pydantic_ai/models/__init__.py:1592-1593`) and is stored in the `_override_model` `ContextVar`; `_pick_raw_model` prefers override > the run's `model=` argument > the agent's default (`SP/pydantic_ai/agent/abstract.py:1665-1705`; `SP/pydantic_ai/agent/__init__.py:2070-2074, 2832-2841`). A `Model` instance passed as `run_sync(model=...)` is returned as-is by `_resolve_model_selection` (`if not isinstance(selection, str): return selection`) and never touches `infer_model`; only strings are resolved (`agent/__init__.py`, `_resolve_model_selection`). `Agent(model, defer_model_check=True)` also skips the constructor-time `infer_model` (`:815-816`).

## C. pydantic-ai-harness 0.29.0

- `FileSystem(root_dir='.', allowed_patterns=..., denied_patterns=..., ...)` yields a `FileSystemToolset` whose `_resolve_path(path)` does `candidate = (self._root / path).resolve()`, then `real = Path(os.path.realpath(candidate))` and `if not real.is_relative_to(self._real_root): raise PermissionError(f'Path {path!r} resolves outside the root directory.')`. Source: `SP/pydantic_ai_harness/filesystem/_toolset.py:228-250`. ## E. Facts that change the design

In priority order, against the planning assumptions (1) provider instance + httpx transport adapter, no Model subclass; (2) the Kernel can refresh the access token and write it back to the Codex auth file without breaking the Codex CLI; (3) cost is reported at OpenAI list price for subscription runs; (4) an expired token's 401 surfaces as a typed exception with a status code.

1. **Assumption (2) is contradicted in its simple form.** Refresh tokens rotate: the refresh response carries a new `refresh_token` that Codex persists, and a reused one is a permanent "refresh token was already used" failure (A2). Codex's writer is a non-atomic truncate-and-write with no cross-process lock, Codex keeps tokens in memory and only re-reads the file in a guarded reload keyed on `account_id`, and OpenAI's own guidance is "Use one `auth.json` per runner … Do not share the same file across concurrent jobs or multiple machines" and "the supported CI/CD strategy is not 'call the refresh API yourself'" (A5.4). If the Kernel refreshes, it must (a) use the same JSON schema (`auth_mode: "chatgpt"`, `tokens.{id_token (raw JWT), access_token, refresh_token, account_id}`, `last_refresh`, `OPENAI_API_KEY: null`), (b) write atomically (temp file + rename, 0600) so a concurrent Codex read never sees a partial file, (c) accept that a Codex process running at the same moment can still refresh first and invalidate the Kernel's refresh token (or vice versa), and (d) note that the docs place "generic OAuth clients outside Codex" outside the supported path. The lower-risk design is to never call `auth.openai.com` from the Kernel: read `auth.json`, and when the access token is within 5 minutes of `exp` (Codex's own rule) or a 401 arrives, let Codex perform the refresh and write the file, then re-read: `codex login status` only loads the store (A6), so the documented trigger is app-server `account/read` ("fetch current account info; optionally refresh tokens", `codex-rs/app-server/README.md:2521`) or any normal Codex run ("Any normal Codex run can refresh the session", A5.4). Reading `exp` needs only base64-decoding the JWT payload.
2. **Assumption (1) holds, with five concrete adjustments** (B8 probe passed end-to-end). (a) openai 3.8.0 and pydantic-ai 2.40.0 are `httpx2`-first: make the adapter an `httpx2.AsyncBaseTransport` inside an `httpx2.AsyncClient`, or accept the `PydanticAIDeprecationWarning` for legacy `httpx` (B1, B9). (b) The Codex backend headers `ChatGPT-Account-ID`, `originator`, `User-Agent`, `session-id`/`thread-id` are not produced by pydantic-ai; supply them via `AsyncOpenAI(default_headers=…)` (through `OpenAIProvider(openai_client=…)`) or `ModelSettings.extra_headers`; pydantic-ai overwrites `User-Agent` with `pydantic-ai/2.40.0` unless `extra_headers` carries one (B1, B2, A3). (c) Codex always sends `store: false`; pydantic-ai omits `store` unless `openai_store=False` is set, so set it (B2, A3). (d) Streaming is the only mode Codex implements and `stream: false` acceptance is unverified, so the rewrite-to-stream adapter is required, not optional; there is no pydantic-ai setting that streams under `run_sync` (B2, A3). (e) Prefer `AsyncOpenAI(api_key=<async callable>)` over header hooks for per-request token injection: it is awaited before every bearer-auth request and needs no transport code (B1, B9). A useful side fact: `include: ["reasoning.encrypted_content"]` is emitted by both pydantic-ai (for reasoning-model profiles) and Codex, so no divergence there.
3. **Assumption (3) holds only for model ids genai-prices 0.1.6 knows.** The provider name stays `openai` for any `base_url`, so pricing falls back to OpenAI list price (B4, probe `cost=Decimal('0.000105')` with a `http://test/backend-api/codex/` base URL). But the slugs the ChatGPT backend actually serves this account are `gpt-6-astra` (the default), `gpt-reserve`, `gpt-5.6-{sol,terra,luna}`, `gpt-5.5`, `gpt-5.4-mini`, `codex-auto-review` (A4); of these `gpt-6-astra`, `gpt-reserve` and `codex-auto-review` are unpriced (`cost=None`), and `gpt-5.4-codex` is unknown too, while `gpt-5-codex` silently prices as `gpt-5`. `RunUsage.cost` skips `None` request costs, so a run mixing priced and unpriced models under-reports rather than reporting unknown. The subscription itself is metered in credits/percent-of-window (`x-codex-primary-used-percent`, app-server `estimatedUsageCreditsMicros`), which the HTTP path does not expose except via those headers; a "list-price equivalent" is a model, not a bill.
4. **Assumption (4) holds.** A 401 reaches the Kernel after exactly one HTTP attempt as `pydantic_ai.exceptions.ModelHTTPError` with `status_code == 401`, `body` (the backend's JSON error), lower-cased `headers` (including any `x-codex-*`), and `__cause__` `openai.AuthenticationError` (B6, probe). Two refinements: a 429 is retried twice by the SDK (0.5 s / 1 s or `retry-after`) before pydantic-ai sees it, so pass `max_retries=0` if the breaker must see the first one; and the Codex 429 body is `error.type: "usage_limit_reached"` with `resets_at` and `plan_type`, plus `x-codex-active-limit`/`x-codex-primary-reset-at` headers, which the breaker can read from `ModelHTTPError.headers`/`body` (A3).
5. Additional facts worth designing around: `auth_mode` may be absent in older `auth.json` files and `account_id` may be null (fall back to the id-token claim) (A1); the local `models_cache.json` is the cheapest offline source for the model list and default (A4); `~` is not expanded by pydantic-settings for a `Path` field, so `CODEX_HOME`-style settings need an explicit `expanduser()` (D); the harness `FileSystem` cannot read `~/.codex/auth.json` from a checkout-rooted toolset, and `denied_env_patterns=['*TOKEN*']` leaves `CODEX_HOME` visible, as intended (C); `logfire.instrument_pydantic_ai()` records only `server.address`/`server.port` of the base URL and never headers or keys, and httpx is not instrumented unless `instrument_httpx` is called (B7); OpenAI documents `codex exec --json`, `codex app-server` (with client-implemented `dynamicTools`, `baseInstructions`, `developerInstructions` and credit-denominated `thread/tokenUsage/updated`) and the Codex SDKs as the programmatic surfaces for a ChatGPT plan, and recommends API keys for automation (A5, A7) — the app-server route is the sanctioned alternative to a transport adapter if the tool-calling loop can live in Codex.
