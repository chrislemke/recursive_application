# Provider Seams: OpenAI with a key, and the ChatGPT subscription through the Codex sign-in

Status: confirmed by the user on 2026-09-06 (open point 1: proceed despite the terms uncertainty; open point 2: the read-only Kernel as planned; the eight decisions stand), written before the first red test of tickets 26 to 28 (`.scratch/recursive-application/issues/`). Derived from the spec (`.scratch/recursive-application/spec.md`, which wins over this document, including its amendment of 2026-09-06 that reopens the out-of-scope line on provider integrations), ADR 0011 (proposed), `CONTEXT.md`, and the research document `thoughts/shared/research/2026-09-06-openai-provider-and-chatgpt-subscription-library-facts.md`. Every fact is cited as `(research Xn)`, the section of that research document that settles it; the document landed in two parts on 2026-09-06 and the amendments at the end record what it changed. The rules of `2026-09-05-phase1-seams.md` apply unchanged: the interface is the test surface, vertical slices, literal expected values, dependencies by category, environment hygiene, and the off-limits list.

Vocabulary: **module, interface, seam, adapter** as in the `codebase-design` skill; domain terms as in `CONTEXT.md` (Operator, Provider, Sign-in, Judge Model, Policy Ceiling).

## The seam, and why it is real now

`AgentRunner(model_factory: Callable[[str], Model])` has existed since ticket 14 with one production adapter, pydantic-ai's `infer_model`, and the test adapters (`FunctionModel`, `TestModel`). A second production adapter, the ChatGPT subscription, makes it a real seam: two things now vary across it. The deep module behind it is `kernel/providers.py`: one factory function hides scheme parsing, the credential check, the Sign-in file, token refresh, header injection, the streaming adapter, and pricing. The Judge Model crosses the same seam, because `set_default_judge_model` accepts a `Model` instance (research B5), so both tiers are built one way and `infer_model` is no longer called by the CLI directly. (Confirmed, research B5: the setter stores a `Model` instance verbatim.)

Deletion test: without `kernel/providers.py`, the credential check, the scheme parsing, and the Sign-in handling reappear in `cli.py`, `runtime.py`, and `eval_tasks.py`. It earns its keep.

## Decisions this document assumes (for the user to confirm)

1. **Model names keep pydantic-ai's syntax.** One new scheme, `chatgpt:<model>` (for example `chatgpt:gpt-5.4`), names the subscription Provider. Every other name delegates to `infer_model`, so `openai:gpt-5.4` with `OPENAI_API_KEY` works with no code beyond the credential check. `chatgpt` rather than `codex`: it names what pays (the ChatGPT plan), matches the `auth_mode` value the Codex CLI writes (`"chatgpt"`, research A1), and leaves `codex` for the CLI.
2. **The Kernel never signs in and never writes the Sign-in.** `codex login` is the Operator's step. The Kernel reads `$CODEX_HOME/auth.json` (default `~/.codex/auth.json`; the schema is research A1) fresh before every request and never prints, logs, traces, or `repr`s a token. Refreshing stays Codex's job: refresh tokens rotate and a reused one fails permanently, Codex's own writer is unlocked and non-atomic, and OpenAI's guidance for automation is not to call the token endpoint yourself (research A2, A5.4, E1). So `require_credentials` refuses to start a run whose access token expires before the run's wall-time budget ends, naming `codex login`, and a token that still expires mid-run surfaces as a 401 model error. A Codex-driven refresh through the app-server's account read is the follow-up if ticket 29 shows runs dying on expiry (open point 2).
3. **Cost stays the list price.** A subscription run reports what the same tokens would cost on the OpenAI API, because pydantic-ai prices by model id and provider name (confirmed, research B4: pricing falls back to the provider name `openai` whatever the base URL, so the list price applies to every model id genai-prices knows; `gpt-5.4-codex` is not among them and would report 0, open point 3). The budget rule keeps binding and `ra status` totals stay comparable. The Run Record does not say which Provider ran (open point 4).
4. **No custom `Model` class.** The subscription Provider is pydantic-ai's `OpenAIResponsesModel` over an `OpenAIProvider` whose `AsyncOpenAI` client points at the ChatGPT backend (the typed route is `OpenAIProvider(openai_client=AsyncOpenAI(...))`, research B1; the backend URL, headers, and body are research A3). The adapter sits at the HTTP transport: it turns the SDK's non-streaming request into the streaming one the backend requires and hands back the completed response as a plain JSON body (confirmed end to end, research B8: the probe adapter there is the seed for `_BackendTransport`, and pydantic-ai reports `requests=1`, the tokens, and a list-price cost through it) . Codex has no unary Responses call and hard-codes `stream: true` and `store: false`; whether the backend accepts `stream: false` could not be verified offline, so the rewrite is mandatory (research A3).
5. **The Kernel identifies itself as itself.** The `originator` and `User-Agent` headers name `recursive_application`. Codex sends `originator: codex_cli_rs` and `User-Agent: codex_cli_rs/<version> (...)`, and the backend can tell the first-party originators apart (research A3, A5.9). If the backend refuses an honest originator, sending the Codex CLI's value is the Operator's explicit choice through `RA_CHATGPT_ORIGINATOR`, not a default, and ADR 0011 records the terms risk (open point 1).
6. **The Policy Ceiling denies the Sign-in directory.** The harness file tool is rooted at the checkout and refuses paths outside it (confirmed, research C: an absolute or `..` path outside the root raises, and `~` and `$HOME` are not expanded, so they name files that do not exist); the shell tool has no path sandbox, so `forbidden_reason` gains a `.codex` rule next to `.env` and `.git`.
7. **Credentials are checked per tier, by scheme, before anything runs**, as `require_api_key` did for OpenRouter, except for `ra status`, whose Providers section is meant to explain a missing key or Sign-in rather than exit on it. For `chatgpt` the check deepens in ticket 28 from "the file exists" to "the Sign-in loads and its token outlives `RA_MAX_MINUTES`".
8. **The Kernel never retries a 429 itself.** The subscription's 429 means the plan's window is used up (`error.type: "usage_limit_reached"` with `resets_at`, research A3); Codex does not retry it either. The OpenAI client runs with `max_retries=0`, so the breaker sees the first one and the SDK never waits out a `retry-after` twice (research B6).

## Module: `kernel/providers.py` (ticket 26; the `chatgpt` branch is wired in ticket 28)

**Interface**
- `CHATGPT_SCHEME = "chatgpt"`.
- `KEYED_SCHEMES: Mapping[str, str] = {"openrouter": "OPENROUTER_API_KEY", "openai": "OPENAI_API_KEY", "openai-responses": "OPENAI_API_KEY", "openai-chat": "OPENAI_API_KEY"}` (the three OpenAI prefixes 2.40.0 knows, research B3; `openai:` builds `OpenAIResponsesModel`).
- `ProviderError(SettingsError)`: a model name without a scheme, a missing key, a missing Sign-in, or a scheme the factory cannot build. The message names the variable, the path, or the command to run, never a value; the CLI already maps `SettingsError` to exit 2.
- `scheme_of(name: str) -> str`. The text before the first `:`; a name without one raises `ProviderError` whose message shows the form `openrouter:anthropic/claude-sonnet-5`.
- `sign_in_path(settings: Settings) -> Path`. `settings.codex_home / "auth.json"`.
- `require_credentials(settings: Settings) -> None`. For each distinct name among `ra_model` and `ra_judge_model`: a keyed scheme needs its Settings field non-blank, else `ProviderError` naming the variable; `chatgpt` needs `sign_in_path(settings).is_file()`, else `ProviderError` naming the path and `codex login` (ticket 26; ticket 28 deepens this to `load_sign_in` and `valid_for`, below); any other scheme is not checked here (pydantic-ai raises its own `UserError` when the model is built).
- `model_factory(settings: Settings, *, clock: Callable[[], datetime] = <UTC now>, transport: httpx2.AsyncBaseTransport | None = None) -> Callable[[str], Model]`. The adapter `AgentRunner` and the Judge Model setter receive. `chatgpt:<m>` (from ticket 28 on) returns `chatgpt_model(m, sign_in_path=sign_in_path(settings), clock=clock, transport=transport, originator=settings.ra_chatgpt_originator)`; every other name returns `infer_model(name)`. Until ticket 28, `chatgpt:` falls through to `infer_model`, which raises `UserError("Unknown model ...")`; no placeholder branch is written.

**Internal**: the scheme table is the only place a scheme is spelled; `runtime.py` and `eval_tasks.py` keep their `Callable[[str], Model]` and `str | Model` parameters unchanged.

**Dependencies**: in-process over `Settings(_env_file=None, ...)` built in the test; the filesystem under `tmp_path` for the Sign-in file; `infer_model` with dummy keys set through `monkeypatch` (construction makes no network call, research C6 of the Phase 2 facts).

**Tracer bullets** (`tests/kernel/test_providers.py`)

2. `require_credentials(Settings(_env_file=None))` raises `ProviderError` matching `OPENROUTER_API_KEY`; with `openrouter_api_key="sk-or-test"` it passes; with `ra_model="openai:gpt-5.4"` and the OpenRouter key set it raises matching `OPENAI_API_KEY`; with `openai_api_key="sk-test"` as well it passes; with `ra_judge_model="chatgpt:gpt-5.4-mini"` and `codex_home=tmp_path` holding no file it raises matching both `auth.json` and `codex login`; after `(tmp_path / "auth.json").write_text("{}")` it passes; `ra_model="anthropic:claude-sonnet-5"` with nothing set passes.
3. `model_factory(settings)("openrouter:x/y")` with `OPENROUTER_API_KEY=sk-or-test` in the environment returns a `Model` with `system == "openrouter"` and `model_name == "x/y"`; `("openai:gpt-5.4")` with `OPENAI_API_KEY=sk-test` returns an `OpenAIResponsesModel` (research B3) with `model_name == "gpt-5.4"`; `("test")` returns a `TestModel`; two calls return two distinct objects.

## Module: `kernel/chatgpt.py`, the Sign-in and the backend adapter (ticket 27)

**Interface**
- `SIGN_IN_FILENAME = "auth.json"`, `MODELS_CACHE_FILENAME = "models_cache.json"`, `BACKEND_URL = "https://chatgpt.com/backend-api/codex"` (research A3), `AUTH_CLAIM = "https://api.openai.com/auth"` (the id token's claim object holding `chatgpt_account_id` and `chatgpt_plan_type`, research A1), `CHATGPT_AUTH_MODES = frozenset({"chatgpt", "chatgptAuthTokens"})` (research A1).
- `SignIn` (frozen dataclass; the token field `repr=False`): `access_token: str`, `account_id: str`, `plan_type: str | None`, `last_refresh: datetime | None`. Read from the Codex schema (research A1): `tokens.access_token`; `tokens.account_id` or, when that is null, the id token's `AUTH_CLAIM` `chatgpt_account_id`; `plan_type` from the same claim's `chatgpt_plan_type`; `auth_mode` must be absent (older files) or in `CHATGPT_AUTH_MODES`. The refresh token and the id token are not kept: the Kernel never refreshes. Property `expires_at: datetime | None`: the access token's JWT `exp` claim as an aware UTC datetime, decoded without verification, `None` when absent. `valid_for(now: datetime, minutes: int) -> bool`: `expires_at` is `None` (no claim; Codex decides by `last_refresh`) or later than `now + minutes`.
- `SignInError(SettingsError)`: missing or unparsable file, an `auth_mode` outside `CHATGPT_AUTH_MODES`, or no `tokens`. The message names the path and `codex login`; it never holds a token.
- `load_sign_in(path: Path) -> SignIn`.
- `served_models(codex_home: Path) -> list[str]`. The model slugs in `codex_home / MODELS_CACHE_FILENAME` (the `slug` of each entry under `models`, in file order, research A4) when the file exists and parses, else `[]`. For `ra status` and the Operator's choice of `RA_MODEL`; never a network call.
- `chatgpt_model(model_name: str, *, sign_in_path: Path, clock: Callable[[], datetime] = <UTC now>, transport: httpx2.AsyncBaseTransport | None = None, originator: str, session_id: str | None = None) -> Model`. An `OpenAIResponsesModel(model_name, provider=OpenAIProvider(openai_client=AsyncOpenAI(base_url=BACKEND_URL, api_key="<replaced per request>", max_retries=0, default_headers={"originator": originator, "User-Agent": "<originator>/<package version>", "session-id": session_id or uuid4()}, http_client=httpx2.AsyncClient(transport=_BackendTransport(...)))))` (research A3, B1, B2; decision 8 for `max_retries`). The client is `httpx2`: pydantic-ai's OpenAI providers use it and warn on a legacy `httpx.AsyncClient` (research B1); the transport, request, response, and `MockTransport` shapes are the same in both (research B9). `httpx2` is today a transitive dependency, so the orchestrator adds `httpx2>=2.12,<3` to `pyproject.toml` before ticket 27 is dispatched (a dependency change, covered by the user's confirmation of this document). Per request the transport, which never raises and always answers with a response: reads the Sign-in from `sign_in_path` fresh (so a refresh by the Codex CLI between two requests is picked up); when the token has expired at `clock()`, answers a synthetic 401 JSON body whose message names `codex login`, without calling the backend; otherwise sets `Authorization: Bearer <access_token>` and `ChatGPT-Account-ID: <account_id>` (research A3), rewrites a non-streaming JSON body to `"stream": true` and `"store": false` and sets `accept: text/event-stream` (Codex hard-codes both fields, research A3; pydantic-ai's `include` and `reasoning` fields match what Codex sends and stay, research B2), reads the event stream through `transport` (default `httpx2.AsyncHTTPTransport()`), and returns a 200 JSON body holding the `response.completed` event's `response`, or a 502 JSON error when the stream ends without one (research B8). A request that already streams passes through untouched. A non-200 status passes through untouched, so the SDK raises its typed error and pydantic-ai maps it to `ModelHTTPError` with `status_code`, `body`, and `headers` (research B6); a 429 body carries `error.type: "usage_limit_reached"` with `resets_at` and `plan_type` (research A3). `model.model_name == model_name` and `model.system == "openai"` so pricing follows the OpenAI list (research B4).

**Internal**: `_BackendTransport(httpx2.AsyncBaseTransport)`; the JWT payload decoder; the event-stream reader (the SDK's own `SSEDecoder`, research B8). Not part of the interface; the tests reach them only through `chatgpt_model` and the SDK.

**Dependencies**: the filesystem under `tmp_path` (real); the backend is a true external, replaced by an `httpx2.MockTransport` handler; time is the injected clock; the model is driven through `Agent(model, output_type=str).run_sync("hi")` with `pydantic_ai.models.ALLOW_MODEL_REQUESTS` patched true for that test only, which is safe because the transport is the mock and nothing reaches the network. Test tokens are literal fake JWTs built in the test (`header.payload.signature` with a base64url JSON payload carrying `exp` and, for the id token, the `AUTH_CLAIM` object with `chatgpt_account_id` and `chatgpt_plan_type`, research A1).

## Open points for the user

1. **Terms.** No sentence in OpenAI's Codex documentation permits or forbids using the ChatGPT Sign-in from a client other than Codex (research A5, "Not found"). What the docs do say: API keys are "the right way to authenticate automation"; the supported way to keep a ChatGPT-managed session alive on a runner is to let Codex refresh and persist `auth.json`, "without calling the OAuth token endpoint yourself" (this plan complies); and that guidance excludes "generic OAuth clients outside Codex" (A5.4). The backend can distinguish clients by the `originator` header (A5.9). OpenAI's Terms of Use and help-center pages could not be fetched (HTTP 403). Secondary reports exist of third-party gateways receiving 429s on the ChatGPT quota (A5, secondary). This is the Operator's risk and the Operator's decision; ticket 27 does not start before it is made. **Decided 2026-09-06: proceed.** If the answer is no, the feature reduces to `openai:` with a key, which ticket 26 delivers on its own.
2. **Refresh** (decision 2). Recommended: the Kernel reads and never writes; a run whose token would expire mid-run is refused before it starts. Alternatives: the Kernel refreshes itself (rotation race with Codex's unlocked writer and the guidance above, research E1), or the Kernel drives Codex's own refresh through `codex app-server` (`account/read` with refresh, research A7), which is sanctioned but a subprocess protocol; the follow-up if expiry bites in practice. The access token's lifetime is not in Codex's source (research A2), so ticket 29 measures it. **Decided 2026-09-06: read-only, as planned.**
3. **Identification** (decision 5): honest `originator` by default, the Codex CLI's value only through `RA_CHATGPT_ORIGINATOR`.
4. **Cost** (decision 3). The models the backend serves this account today are `gpt-6-astra` (the default), `gpt-reserve`, the `gpt-5.6` family, `gpt-5.5`, `gpt-5.4-mini`, and `codex-auto-review` (research A4); of these genai-prices knows `gpt-5.5` and `gpt-5.4-mini` only, so a run on the default model reports `0` and runs under the token fallback alone (research B4, E3). Decision 3 stands for the priced ids. A Kernel price table for the unpriced ones is not planned; reporting `0` everywhere for subscription runs is the alternative.
5. **The Run Record does not name the model or the Provider.** Adding `model: str` and `judge_model: str` to `RunRecord` (defaulted, so old files still load) would make a subscription run distinguishable later. Not planned; one line each if wanted.
6. **Rate limits** (decision 8). A `usage_limit_reached` 429 is one model error: the run ends as errored with the backend's message in its reason, and three in a row open the role's breaker for `RA_BREAKER_RESET_S`. Reading the plan's remaining quota (`x-codex-primary-used-percent`, `resets_at`) into `ra status` or a Sensor Finding is not planned.
7. **`ra status` no longer requires credentials** (decision 7); every other command still does, as before.
8. **`CODEX_HOME` semantics** follow Codex: the directory must exist (research A1). The default `~/.codex` is the Codex CLI's own.
