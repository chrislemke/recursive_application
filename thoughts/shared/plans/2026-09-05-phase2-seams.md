## Module: `organism/wiki.py` and the seed `wiki/` (ticket 08)

**Interface**
- Constants: `INDEX_FILENAME = "index.md"`, `LOG_FILENAME = "log.md"`, `PAGES_DIRNAME = "pages"`, `CATEGORIES = ("capabilities", "lessons", "open-questions", "tasks")`, `FRONTIER_PROPOSAL_PREFIX = "next-frontier-"`.
- `OpenQuestion(path: str, title: str, capability: str | None)`, `CapabilityPage(name: str, path: str, commit: str | None, dataset: str | None)`, `LintReport(orphans: list[str], unindexed: list[str])` with an `is_clean` property. Frozen dataclasses; every `path` is POSIX relative to the Wiki root (`pages/lessons/x.md`).
- `class Wiki(root: Path, clock: Callable[[], datetime] = UTC now)`. `root` is the `wiki/` directory.
  - `ensure_layout() -> None`. Creates `index.md` (as `rebuild_index` would render it), `log.md` (with the heading `# Wiki log`), and the four category directories each holding a `.gitkeep`; idempotent; never overwrites an existing file.
  - `pages() -> list[str]`. Every `*.md` under `pages/`, sorted.
  - `rebuild_index() -> str`. Renders the index from the pages and writes it to `index.md`; returns the text. Format: `# Wiki index`, then one `## <Category>` section per entry of `CATEGORIES` in that order (`Capabilities`, `Lessons`, `Open questions`, `Tasks`), each holding one line per page sorted by path, `- [<title>](<path>): <first paragraph>`, or `- (none)` for an empty category. Title is the first `# ` heading's text, else the file stem. First paragraph is the first non-empty, non-heading block, joined to one line and cut at 200 characters. Deterministic: same pages, same text.
  - `index_text() -> str`. The current `index.md`, `""` when missing.
  - `append_log(entry: str) -> None`. Appends the line `- <clock() as ISO 8601 UTC, seconds, Z>: <entry>` to `log.md`; earlier lines are never touched.
  - `list_open_questions() -> list[OpenQuestion]`. Every page under `pages/open-questions/`, sorted by path; `capability` is the part of the file name after `next-frontier-` for a frontier proposal, else `None`.
  - `lint_report() -> LintReport`. `unindexed`: pages that `index.md` does not link to. `orphans`: pages that nothing links to, the index, the log, and every other page included. Links are markdown `](target)` targets resolved relative to the linking file. Both lists sorted.
  - `capability_page(name: str, summary: str, *, commit: str, dataset: str) -> str`. The capability page convention: `# <name>`, a blank line, the summary, a blank line, `- Commit: <commit>`, `- Dataset: <dataset>`.
  - `list_capabilities() -> list[CapabilityPage]`. Every page under `pages/capabilities/` parsed by that convention; a missing line gives `None`.

**Seed files** (tracked): `wiki/index.md` and `wiki/log.md` as `ensure_layout` writes them, and `wiki/pages/<category>/.gitkeep` for the four categories.

**Dependencies**: filesystem under `tmp_path`; injected clock.

## Module: `kernel/policy.py`, the Policy Ceiling (ticket 09)

**Interface**
- `ToolConfig` (a Kernel contract: frozen, unknown fields rejected): `files: bool = True` (whether the agent has a file tool at all), `write_globs: list[str] = []` (where its file tool may write; empty means read-only), `shell_commands: list[str] = []` (the first tokens its shell tool accepts; empty means no shell), `git_read: bool = False` (the five read-only git tools), `shell_timeout_s: int = 600`.
- `PolicyError(ValueError)`; its message names the offending value.
- The ceiling, Kernel-owned constants: `FORBIDDEN_COMMANDS: frozenset[str]` (git, package managers and their installers such as `pip`, `pip3`, `uvx`, `npm`, `brew`, `apt`; network clients such as `curl`, `wget`, `ssh`, `scp`, `nc`; deleting and editing utilities such as `rm`, `mv`, `cp`, `sed`, `awk`, `tee`, `dd`, `chmod`, `vi`, `vim`, `nano`; environment readers `env`, `printenv`; `sudo`); `FORBIDDEN_SUBCOMMANDS: Mapping[str, tuple[tuple[str, ...], ...]]` (`uv`: `add`, `remove`, `pip`, `sync`, `lock`, `tool`, `publish`, `self`; `python` and `python3`: `-m pip`); `DENIED_OPERATORS: tuple[str, ...]` (`|`, `&&`, `||`, `;`, `>`, `<`, `` ` ``, `$(`); `UNREADABLE_PATTERNS = (".env", ".git/**")`; `SECRET_ENV_PATTERNS = ("*_API_KEY", "*TOKEN*", "*SECRET*")`; `NETWORK_ALLOWED = False`.
- `validate_tool_config(config: ToolConfig) -> None`. Raises `PolicyError` for the first violation: a shell command in `FORBIDDEN_COMMANDS` or not a single bare word; a write glob outside the write-scope allowlist (`writable_globs()` from `kernel/paths.py`: a glob is inside when it equals an allowlist entry or starts with a writable directory followed by `/`).
- `forbidden_reason(command: str) -> str | None`. For one shell command line: the denied operator it contains, the forbidden first token, the forbidden subcommand (`uv add`), or an unreadable path it names (`.env` as a whole token or path segment, `.git` as a path or path prefix; the harness shell has no path sandbox, so this is where the ceiling's read rule reaches the shell), else `None`. The Organism's shell wrapper calls this before every run.

**Dependencies**: in-process.

**Tracer bullets** (`tests/kernel/test_policy.py`)
1. `validate_tool_config(ToolConfig())` and `validate_tool_config(ToolConfig(write_globs=["tests/organism/**"], shell_commands=["uv", "pytest"]))` return `None`.
2. `ToolConfig(shell_commands=["git"])` raises `PolicyError` with `git` in the message; likewise `rm`, `curl`, `pip`, `sed`, and the two-word entry `"uv run"`.
3. `ToolConfig(write_globs=["docs/**"])` raises with `docs/**` in the message; likewise `src/recursive_application/kernel/**`, `.ra/**`, `.venv/**`, and `tests/**`; `["wiki/pages/**"]` and `["README.md"]` pass.
4. `forbidden_reason("uv run pytest")` and `forbidden_reason("python -c \"print(1)\"")` are `None`; `forbidden_reason("uv add requests")` contains `uv add`; `"git status"` contains `git`; `"python -m pip install x"` contains `pip`; `"cat a | tee b"` contains `|`; `"ls; rm -rf /"` contains `;`; `"cat $(ls)"` contains `$(`.
5. `forbidden_reason("cat .env")` and `forbidden_reason("python -c \"open('.env').read()\"")` contain `.env`; `"cat .git/config"` and `"ls .git"` contain `.git`; `"cat .gitignore"` and `"cat .env.example"` are `None`.

## Module: `organism/tools.py`, the tool configurations (ticket 09)

**Interface**
- `SHELL_COMMANDS: tuple[str, ...] = ("uv", "pytest", "python", "ruff", "ty", "rg", "grep", "ls", "cat", "head", "tail", "wc", "diff")`.
- `ROLE_TOOL_CONFIGS: Mapping[str, ToolConfig]` keyed `triage`, `planner`, `test_writer`, `implementer`, `worker`, `reviewer`, `librarian`:
  - `triage`: `ToolConfig(files=False)`.
  - `planner`: `ToolConfig(git_read=True)`.
  - `test_writer`: `ToolConfig(write_globs=["tests/organism/**"], shell_commands=list(SHELL_COMMANDS))`.

  - `worker`: `ToolConfig()` (read-only file tool, no git: the repo-history Frontier Cases are red by design until a Growth Loop exposes git to an Act-phase agent).
  - `reviewer`: `ToolConfig(git_read=True)`.
  - `librarian`: `ToolConfig(write_globs=["wiki/**"])`.
- `toolsets_for(config: ToolConfig, root: Path) -> list[AbstractToolset[Any]]`. Builds, for an agent, the toolsets its configuration grants, all rooted at `root` (the checkout, or a temporary layout in tests):
  - a file toolset (the harness `FileSystem`) when `files`: reads anywhere under `root` except `UNREADABLE_PATTERNS`; when `write_globs` is empty only the read-only tools are exposed; otherwise a write (`write_file`, `edit_file`, `create_directory`) is accepted only when the path is inside one of `write_globs` and `is_writable(path, root)` holds, and refused with a reply naming the path otherwise;
  - a shell toolset (the harness `Shell`) when `shell_commands` is non-empty: `allowed_commands=shell_commands`, `denied_operators=DENIED_OPERATORS`, `default_timeout=shell_timeout_s`, `denied_env_patterns=SECRET_ENV_PATTERNS`, and `forbidden_reason` applied before each run so a forbidden subcommand is refused with its reason;
  - a git toolset when `git_read`: function tools `git_log(n: int = 20, path: str | None = None)`, `git_show(ref: str = "HEAD")`, `git_blame(path: str)`, `git_status()`, `git_diff(ref: str = "HEAD", path: str | None = None)` over `Repo(root)`'s read helpers; a `GitError` is returned as the tool's reply text, never raised through the agent.
- `ToolDescription(name: str, description: str)`, a frozen dataclass. `describe_tools(config: ToolConfig, root: Path) -> list[ToolDescription]`. The name and the first sentence of the description of every tool `toolsets_for(config, root)` exposes, sorted by name; the Capability Inventory (ticket 13) renders these, so it reflects the tools an agent really has.
- Invariants: `git` is never on the shell allowlist; nothing writes under `.venv/` or `.ra/`; no tool reaches the network; every `ROLE_TOOL_CONFIGS` entry passes `validate_tool_config`.

**Dependencies**: the harness `FileSystem` and `Shell` in-process; the filesystem under `tmp_path` laid out like the checkout (`src/recursive_application/organism/`, `tests/organism/`, `wiki/`, `README.md`, `.env`, `.ra/`, `.venv/`); the real git binary through the `git_repo` fixture; `Agent(FunctionModel(...))` to drive one tool call and return its reply, through a helper `call_tool(toolsets, name, args) -> str` in `tests/organism/conftest.py`.

## Module: `kernel/evals.py`, datasets and reports (ticket 10)

**Interface**
- Constants: `EVALS_DIR = REPO_ROOT / "evals"`, `FRONTIER_DIRNAME = "frontier"`, `LATEST_POINTER = "latest.json"`, `CUSTOM_EVALUATOR_TYPES: tuple[type[Evaluator], ...] = ()` (ticket 15 fills it).
- `DatasetError(ValueError)`.
- `list_datasets(evals_dir: Path = EVALS_DIR) -> list[Path]`. Every `*.yaml` under `evals_dir`, recursively, sorted.
- `dataset_name(path: Path, evals_dir: Path = EVALS_DIR) -> str`. `triage` for `evals/triage.yaml`, `frontier/text-analysis` for `evals/frontier/text-analysis.yaml`.
- `load_dataset(path: Path) -> Dataset`. `Dataset.from_file(path, custom_evaluator_types=CUSTOM_EVALUATOR_TYPES)`; a bad file raises `DatasetError` naming the path.
- `FrontierCase(Contract)`: `name`, `capability`, `rung: int`, `gap_kind: Literal["tool", "knowledge", "connection", "skill", "clarification"]`, `needs_human: list[str] = []`. `validate_frontier(path: Path) -> list[FrontierCase]`: every case must carry `metadata` with `tier: frontier`, `capability` equal to the file stem, `rung`, and `gap_kind`; rungs must be `1..n` in file order; otherwise `DatasetError` naming the case and the fault.
- Report contract: `CaseResult(Contract)`: `dataset: str`, `name: str`, `passed: bool`, `reasons: list[str] = []`, `metadata: dict[str, Any] = {}`. `EvalReport(Contract)`: `created_at: datetime`, `run_id: str | None = None`, `datasets: list[str]`, `cases: list[CaseResult]`; `case(dataset, name) -> CaseResult | None`; `summary_lines() -> list[str]` one per dataset sorted, `<dataset>: <passed>/<total> passed`. Case keys elsewhere are `<dataset>/<name>`.
- `results_from(dataset: str, report: EvaluationReport) -> list[CaseResult]`. A case passes when every assertion is true and no evaluator failed; a failed assertion contributes `<assertion name>: <reason>` to `reasons`; a task failure (`report.failures`) becomes a failed result with the error message; the case's `metadata` is copied.
- `ReportStore(reports_dir: Path)`: `save(report) -> Path` writes `<run_id or created_at as %Y%m%d-%H%M%S>.json` and `latest.json` holding `{"report": "<file name>"}`; `load_latest() -> EvalReport | None`; `list_all() -> list[EvalReport]` in `created_at` order, `[]` when the directory is missing.
- `EvalDelta(Contract)`: `targets: list[str]`, `targets_passed_before: int`, `targets_passed_after: int`, `newly_passing: list[str]`, `newly_failing: list[str]`, `guard_regressions: list[str]`, with properties `target_improved` (`after > before`) and `guard_regressed` (non-empty regressions). `compare(before: EvalReport | None, after: EvalReport, targets: Iterable[str]) -> EvalDelta`: a case missing from `before` counts as failing; a case missing from `after` was not run and is neither a pass nor a regression; a guard regression is a non-target case that passed before and fails now.
- `FrontierRatio(Contract)`: `capability`, `green: int`, `total: int`, `lowest_red_rung: int | None`, property `available` (`total > 0 and green == total`). `frontier_ratios(frontier_dir: Path, report: EvalReport | None) -> list[FrontierRatio]` sorted by capability, `green` counted over dataset `frontier/<capability>` in `report`, a missing case red.
- `changed_eval_cases(before_yaml: str | None, after_yaml: str | None) -> list[str]`. Names of cases present in `before` that are absent from `after` or differ in any field; appended cases are allowed; `before=None` gives `[]`; `after=None` names every case of `before`. Works on the raw YAML mapping so a schema-invalid file still compares.
- Git amendment (`kernel/git.py`): `Repo.file_at(ref: str, path: str) -> str | None`, the file's content at `ref` (`git show <ref>:<path>`), `None` when the path does not exist there, `GitError` for a dash-prefixed `ref` or `path`.

**Dependencies**: pydantic-evals in-process; the filesystem under `tmp_path`; the real frontier files under `evals/frontier/`; the `git_repo` fixture for the amendment. No model: probe datasets use `Contains` and `EqualsExpected` with a plain function as the task.

## Open points for the user

- The write scope's `evals/**` entry stays in the Kernel allowlist (the spec lists it) even though no agent's configuration names it; the Kernel appends Target Cases through its own code, not through a tool.
- The Worker starts without git tools on purpose, so the repo-history ladder is red until a Growth Loop exposes them; if the user would rather see the Worker read history from day one, the config is one line.
- `forbidden_reason` denies pipes and redirections outright; the Implementer loses `uv run pytest | tail`, and gets the truncated output the harness returns instead.

## Datasets: the seven seed files (ticket 11)

Not a module: seven Organism files under `evals/`, plus one Kernel test. The shapes below are also the contract ticket 15's task functions implement, so the two tickets agree on them here.

**Rendering convention.** Every task function returns text. A contract (`TriageDecision`, `Plan`, `Review`, `CodeReport`) is rendered as YAML with `yaml.safe_dump(model.model_dump(mode="json"), sort_keys=False)`, so `Contains: "mode: growth"` and `Contains: "kind: skill"` are exact, cheap assertions and `LLMJudge` reads the same text. The Worker's `content` and the Librarian's summary are rendered as they are.

**Inputs shape per dataset** (`inputs` in YAML):

**Interface**

## Module: `kernel/loop.py`, the Loop runner (tickets 18 to 22)

The primary seam for the Loop, escalation, gap recording, stop rules, commit and reset, and the Librarian calls. Tickets 19 to 22 add cases to the list at the end of this section before their tests; the interface is fixed here.

**Interface**
- `LoopOptions(Contract)`: `yes: bool = False`, `max_iterations: int | None = None`, `budget_usd: Decimal | None = None`, `max_minutes: int | None = None`, `goal: str | None = None`. `None` means the Settings value.
- `EvalRequest(Contract)`: `run_id: str`, `datasets: list[str] = []` (names under `evals/`), `task_dataset: str | None = None` (an absolute path to a runtime `cases.yaml`), `output: str | None = None` (the produced text the task dataset judges; the eval runner's task function returns it unchanged), `targets: list[str] = []` (case keys).
- `Runners` (frozen dataclass of adapters the CLI wires and tests replace): `checks: Callable[[Path], list[CheckResult]]`, `red_check: Callable[[Path, Sequence[str]], RedResult]`, `evals: Callable[[EvalRequest], EvalReport]`, `approve: Callable[[str], bool]` (shows the YAML, returns the decision), `clock: Callable[[], datetime]`.
- `LoopResult` (frozen dataclass): `record: RunRecord`, `output: str | None` (the Answer or Task output of the last Iteration), `reason: str | None` (why the run stopped, was refused, or was rejected), `questions: list[str]` (Triage's clarifying questions), `exit_code: int` (0 accepted, 1 rejected or best-effort, 2 aborted or usage error, 3 internal error).
- `ANSWER_RUBRIC: str`, the generic Answer rubric (a Kernel constant): the Answer addresses the request directly, is grounded in the Capability Inventory and the repository when it speaks about the system, states what it could not do, and adds no claim it cannot support.
- `LOCK_FILENAME = "lock"`, `TASKS_DIRNAME = "tasks"`, `FALLBACK_USD_PER_MILLION_TOKENS = Decimal("3")`.
- `estimated_cost(usage: Usage) -> Decimal`. `cost_usd` when positive, else `(input_tokens + output_tokens) / 1_000_000 * FALLBACK_USD_PER_MILLION_TOKENS` (the token fallback).
- `LoopRunner(*, settings: Settings, registry: Registry, agents: AgentRunner, repo: Repo, wiki: Wiki, root: Path, ra_dir: Path, runners: Runners, breakers: BreakerStore)`:
  - `run(mode: Mode | None, task: str | None, options: LoopOptions) -> LoopResult`. `mode=None` with a task is `ra ask` (Triage decides); `Mode.GROWTH` with `task=None` is `ra improve` (the top finding, or the goal with the findings).
- `RunRecord` gains nothing; `IterationRecord.output_path` points at `<ra_dir>/tasks/<run_id>/output.md` for Answer and Task Iterations. `Plan` gains `dataset: str | None = None` (records amendment): the dataset under `evals/` the Plan's Target Cases are appended to; `None` when the targets are existing Frontier Cases (then `target_cases` name them and nothing is appended).

**Semantics**
- Every agent call goes through `agents.run(entry, prompt, bundle=assemble_state_bundle(position, ...))` with a `LoopPosition` naming the run, Mode, Iteration and limit, the phase and role, and the previous Iteration's Gate outcome. Sense is `sensors.collect(...)` at the start of the run; its result feeds Triage and the Planner.
- Decide: with `mode=None`, Triage runs on the task and the findings. A gap of kind `clarification` ends the run: `questions` filled, outcome `aborted`, reason `clarification`, exit 2, nothing else runs. Otherwise the decision's Mode is used and recorded.
- Answer: no Planner. The Kernel writes one Target Case (`name=f"answer-{run_id}"`, `inputs=task`, `rubric=ANSWER_RUBRIC`, as an `LLMJudge` case) to `<ra_dir>/tasks/<run_id>/cases.yaml`. Each Iteration: the Worker runs with the task (on retries, the previous judge reason appended under `Previous attempt failed because:`); `content` is written to `output.md`; the Gate gets `eval_delta` from `compare(latest persisted report, runners.evals(EvalRequest(task_dataset=..., output=..., targets=[...])), targets)`, `anomalies` from `trace_findings` over this run's spans, `review=None`. Accepted when the Gate passes (exit 0). After the iteration limit the last output is returned with `reason="best effort: the judge never passed the Answer"`, outcome `rejected`, exit 1, and a `reflection` finding is appended to the `FindingStore`.
- Task Loop: the Planner runs with the task and findings. A Plan with `gaps` escalates: Mode becomes Growth with a fresh approval. Otherwise the Kernel writes `plan.target_cases` to `cases.yaml` under the run's task directory, never into `evals/`, and asks `runners.approve(<Plan and cases as YAML>)` unless `options.yes`; a refusal aborts with reason `approval refused`. The Actor is `plan.actor or "worker"`; an unknown name, or a name that is not `worker` and not a Specialist, rejects the Iteration before Act with reason `unknown actor: <name>` and counts as no progress. The Actor's `WorkerOutput.content` goes to `output.md`; its `gaps` escalate to Growth with a fresh approval. The Gate runs `evals`, `anomalies`, and `review` (the Reviewer sees the Plan and the output). Gaps that were recognised but not escalated (the run ended first, or the gap lists `needs_human`) are appended to the `FindingStore` as `reflection` findings with ids `reflection:<run_id>:<n>`.
- Growth Loop: refused with reason `dirty working tree` when `repo.is_clean()` is false, and with `lock held` when `<ra_dir>/lock` exists; the lock holds the run id and is removed when the run ends, however it ends. The Planner runs with the task or the finding (or the goal and the findings). Before Act, in this order, an Iteration is rejected with a named reason and no progress: a Plan whose `target_paths` include a Protected Path, the Coding Guide, a frontier file, or `kernel/policy.py`'s ceiling (reason `policy`, plus a `policy` finding addressed to the human in the `FindingStore`); a Python target with empty `tests` (reason `no tests`); an Actor that is neither `implementer` nor a Specialist (reason `unknown actor`). New Target Cases (names not in the dataset) are appended to `plan.dataset`; nothing is appended when `dataset` is `None`. Approval as above. Act: when any target path ends in `.py`, the Test Writer runs, the changed files under `tests/organism/` go to `runners.red_check`, and a result that is not red rejects the Iteration with reason `no red` and the output in the record; then the Actor runs. When no target path is Python the Test Writer is skipped and the Target Cases, red in the latest report, are the red. Gate inputs, gathered in `CHECK_ORDER`'s order and stopping at the first failure: `diff_paths=repo.changed_paths()`; `changed_eval_cases` over every changed path under `evals/` with `repo.file_at("HEAD", path)`; `runners.checks(root)`; the Guard subset `[plan.dataset or the targets' frontier dataset, "triage", "answers", *affected agents' datasets]` deduplicated through `runners.evals`, with a second `runners.evals` over the datasets of any guard regressions filling `guard_retry_passed`; `trace_findings` over this run's spans; the Reviewer on the diff and the Plan. Accepted: the Librarian runs with the run summary (it writes through its Wiki tool), `wiki.rebuild_index()` and `wiki.append_log(...)` run, and `repo.commit_all(f"ra: {plan.title}")` records the sha in the Iteration. Rejected: `repo.reset_hard_clean()`, then the Librarian records the lesson, then `repo.commit_all(f"ra: lesson from {run_id}")` so the tree stays clean for the next Iteration and the next run.
- After an accepted Improvement in `ra ask` (`mode=None`), Triage runs once more on the original task: Answer or Task Loop then run under the remaining iteration, time, and budget limits inside the same Run Record; Growth again stops with reason `growth needed twice`, exit 1, and `output` naming what was added and what is still missing. `ra improve` continues to the next finding after each accepted Improvement until a stop rule.
- Stop rules, each ending the run with outcome `aborted` and a named reason: `iteration limit` (`options.max_iterations` or `settings.ra_max_iterations`), `wall time` (`runners.clock` against the start), `budget` (`estimated_cost` summed over the run against `options.budget_usd` or `settings.ra_budget_usd`, checked before each Iteration; each agent call also gets the remaining budget as its cost limit), `no progress` (`settings.ra_no_progress_iterations` consecutive Iterations that were rejected without a newly passing Target Case), `breaker open: <name>` (a `CircuitOpenError`). An unexpected exception ends the run with outcome `error`, exit 3, and the exception's text as the reason.
- Every Iteration is appended to the Run Record through `RunStore(ra_dir / "runs")` as it ends, with its usage, so a crash leaves the record behind.

**Interface**
