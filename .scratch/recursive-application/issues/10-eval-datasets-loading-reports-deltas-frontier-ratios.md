# 10: Eval datasets: loading, reports, deltas, frontier ratios, append-only rule

**What to build:** The Kernel can load any dataset file, persist an eval report with a pointer to the latest one, compute Target and Guard deltas between two reports where a case missing from the earlier report counts as failing, compute the frontier ratio per capability, and detect changed or deleted existing eval cases from a diff. The three seeded frontier ladders are validated as a Kernel test.

Source: spec section "Evals and traces" and Testing Decisions seams 4 and 11; ADRs 0005 and 0009.

**Blocked by:** 03 (Data contracts and the Run Record), 06 (Git as the state store)

**Status:** done

- [ ] The seam is written in the seams-document format and confirmed by the user before the first red test
- [x] Every file under the frontier directory loads with the pydantic-evals loader; every case carries tier, capability, rung, and gap kind; rungs are consecutive from 1
- [x] A report is persisted per run under the runtime directory's evals folder with a latest pointer; its schema records each case's pass or fail and assertion reasons and is a Kernel contract
- [x] Comparing two reports yields Target improved and Guard regressed deltas; a case with no entry in the earlier report counts as failing, so a new dataset starts red
- [x] Frontier ratios are computed as green over total per capability; a capability is available only when green equals total
- [x] Given a diff of eval files, changed or deleted existing cases are named and appended cases are allowed
- [x] No model is called in tests
- [x] All four checks exit 0

No model is called anywhere: the probe datasets pair `Contains` and `EqualsExpected` with `lambda inputs: inputs` as the task, and the seeded frontier ladders are only loaded and validated, never run.

`list_datasets` is `rglob("*.yaml")` sorted, `dataset_name` the path below `evals/` without its suffix, so a frontier ladder is the dataset `frontier/<capability>`. `load_dataset` calls `Dataset[str, str, dict[str, Any]].from_file(path, custom_evaluator_types=CUSTOM_EVALUATOR_TYPES)` and re-raises the loader's `ValueError` as `DatasetError` with the path in front; the explicit generic parameters are there because a bare `Dataset.from_file` warns that it cannot determine them. `validate_frontier` reads each case's `metadata`, requires `tier`, `capability`, `rung` and `gap_kind` to be present, `tier` to be `frontier`, `capability` to equal the file stem, and the rung to equal the case's position in file order, and names the offending case in every message. `results_from` turns a `EvaluationReport` into `CaseResult` contracts: a case passes when every assertion is true and no evaluator failed, a false assertion contributes `<name>: <reason>`, and every entry of `report.failures` (a task that raised, for which pydantic-evals emits no `ReportCase` at all) becomes a failed result carrying the error message. `ReportStore` writes `<run_id>.json`, or `<created_at as %Y%m%d-%H%M%S>.json` when there is no run id, and a `latest.json` holding `{"report": "<file name>"}`; `load_latest` follows that pointer and returns `None` when it is missing, `list_all` reads every other `*.json` and orders them by `created_at`. `compare` treats a case with no entry in the earlier report as failing, which is what makes "Target improved" well defined for a dataset that has never run. `frontier_ratios` counts each ladder against the report and reports the lowest red rung, so the eval Sensor can emit one finding per capability. `changed_eval_cases` works on `yaml.safe_load` of the raw text, keyed by case name and comparing whole mappings, so a file the loader would reject still compares and the append-only rule of ADR 0005 is enforceable at the Gate. `Repo.file_at` is `git show <ref>:<path>` with the module's fixed argv style, both arguments passed through `_refuse_option` first.

Deviations and judgement calls for the human to confirm:

- **Contracts in this module use `Field(default_factory=list)` where `records.py` writes `= []`.** Ruff's RUF012 recognises a Pydantic model by its bases within the file; `Contract` is imported here, so the bare mutable defaults are flagged. Behaviour is identical.
- **Case keys split at the last `/`, not the first.** The seams document says case keys are `<dataset>/<name>` and, separately, that a frontier dataset is named `frontier/<capability>`, so a Frontier Case key is `frontier/repo-history/repo-history-1-first-commit`. `compare` therefore resolves a key with `rpartition("/")`. A test states this, since Target Cases may be existing Frontier Cases.
- **`CaseResult.name` is `source_case_name or name`.** With `evaluate_sync(..., repeat=K)` pydantic-evals renames cases to `a [1/K]` and keeps the original in `source_case_name`; a repeated run therefore yields K results under the one case name. Verified with a test at `repeat=2`.
- **`newly_passing` and `newly_failing` cover every case in the later report, not only the Target Cases**, and `guard_regressions` is the non-target part of `newly_failing`. The seams document does not say which scope; the wider one loses nothing and the Gate only reads the target counts and the regressions.
- **A failed assertion with no reason contributes just the assertion name.** `EqualsExpected` returns `reason=None` in this version, so the documented `<assertion name>: <reason>` would have read `EqualsExpected: None`.
- **An evaluator failure counts against a case but no test exercises it.** `CUSTOM_EVALUATOR_TYPES` is empty until ticket 15 and every default evaluator catches its own errors (a probe with `Contains` against a mapping value produced a failed assertion, not an evaluator failure), so the branch is written from the interface and unproven.
- **`validate_frontier` checks `tier` and `capability` as well as `gap_kind`**, with two tests beyond the bullet's list, because the interface requires all four metadata keys.
- **`summary_lines()` counts the datasets that produced cases**, not `EvalReport.datasets`, so a dataset that ran and produced nothing gets no line.
- **`load_dataset` catches `ValueError` only.** Pydantic's `ValidationError` is one, so a schema-invalid file becomes a `DatasetError`; a file that is not YAML at all raises `yaml.YAMLError` unchanged.
- **`Repo.file_at` does not truncate at the module's read limit**, unlike the five read helpers, because the Gate compares whole eval files with it and a cut text would read as a changed case. Absence is git's `does not exist` or `exists on disk, but not in`; every other failure raises `GitError`.
- **Bullet 3's literal is asserted with the metadata included**: `CaseResult(dataset="probe", name="a", passed=True, metadata={"tier": "frontier", "rung": 1})`, since the same bullet requires the case's metadata to come back unchanged.
- **Eight tests were green on their first run.** `test_load_dataset_raises_a_dataset_error_naming_a_file_that_breaks_the_schema` and `test_a_report_without_a_run_id_is_saved_under_its_creation_timestamp`, because the `DatasetError` wrapper and the timestamp file name were part of the interface line implemented one step earlier; `test_a_target_case_that_already_passed_is_not_an_improvement` and `test_a_target_case_that_passed_before_and_fails_now_is_newly_failing_not_a_regression`, `test_a_frontier_capability_reports_the_lowest_rung_that_is_still_red` and `test_a_capability_is_available_only_when_every_rung_of_its_ladder_is_green`, `test_a_new_dataset_file_has_no_existing_case_to_change` and `test_a_dataset_level_evaluator_is_not_an_eval_case`, because the general implementation each bullet's first test forced already covered the bullet's remaining sub-cases; the alternative was writing code known to be wrong for one cycle.
