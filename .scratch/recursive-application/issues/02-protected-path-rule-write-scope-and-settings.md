# 02: Protected Path rule, write scope, and Settings

**What to build:** The Kernel can answer, for any path, whether the Organism may ever modify it and whether a tool may write to it, and can load its Settings from the environment and an env file with the spec's exact defaults. Every later Kernel module has one source of truth for the Protected Path rule, the write-scope allowlist, the runtime directory, and configuration.

Source: the Phase 1 seams document, paths module (nine tracer bullets) and settings module (five tracer bullets); spec section "Kernel, Organism, Protected Paths, and the write scope".

## Comments

**2026-09-05, implemented.** The Protected Path rule and the write scope in `src/recursive_application/kernel/paths.py`, and `Settings` in `src/recursive_application/kernel/settings.py`, built red to green from the seams doc's nine paths bullets and then its five settings bullets, in order (58 tests as pytest counts them: 17 functions in `tests/kernel/test_paths.py` and 11 in `tests/kernel/test_settings.py`, several parametrised). The rule is four module-level tuples (protected directories and files, writable directories and files); `is_protected`, `is_writable`, and both glob functions read them and nothing else. A relative path is normalised (`./` dropped, `..` collapsed) and one that climbs above the root is outside; an absolute path is resolved through symlinks and compared against the resolved root, which is what makes `tmp_path` under `/var` on macOS work. `Settings` has no `env_file` in its config, so nothing is ever read from the working directory; `load_settings` passes the file explicitly, defaulting to `REPO_ROOT/.env`, and the tests always name a file under `tmp_path` or pass `_env_file=None`. Library facts came from `thoughts/shared/research/2026-09-05-settings-tracing-library-facts.md`, section A: `_env_file` selects the file and `None` disables it, a missing file is skipped silently (A1); precedence init > environment > dotenv (A2); `extra="ignore"` for keys the file holds for other tools (A3); `env_ignore_empty=True` so `LOGFIRE_TOKEN=` reads as `None` without breaking blank numeric fields (A4); python-dotenv strips unquoted values but real environment variables are never stripped, hence the validator on the key (A5); case-insensitive matching of `RA_*` names (A6).

Deviations for the human to confirm:

- **One interface function added: `resolve_repo_root(env: Mapping[str, str] | None = None) -> Path`**, with `REPO_ROOT = resolve_repo_root()`. The criterion "honours the override variable" cannot be tested against an import-time constant without reloading the module, so the override is tested through this function with a plain dict. The override value is resolved (`Path(value).resolve()`); without it the function walks up from this package to the first ancestor holding `pyproject.toml` and `src/`, and raises `RuntimeError` at import when there is none (an installed wheel outside a checkout without `RA_REPO_ROOT`).
- **A blank key is not exported.** The seams doc says `load_settings` exports `OPENROUTER_API_KEY` and `LOGFIRE_TOKEN`; the implementation exports each only when it carries a value (a non-empty key, a token that is not `None`), because an empty variable gives the provider nothing to find and would shadow a later, fuller load under `env_ignore_empty`.
- **Bullets with no red.** Paths 3 (Organism paths not protected), the `REPO_ROOT` half of paths 7, paths 8 (plans and scratch), and settings 3 (environment over file) were green as written, because the rule is a positive list, `REPO_ROOT` had entered in bullet 4 as the default root, and precedence is pydantic-settings' default. Each was checked against a one-line mutation (widening the Kernel entry to `src`, returning the ancestor's parent, deleting `thoughts` and then `.scratch` from the rule, swapping the environment and dotenv sources) and went red; every mutation was reverted and the file compared byte for byte against a backup. Two settings tests passed vacuously before their code existed (a blank token is not exported; a user-set variable is not rewritten) and were mutation-checked the same way.
- **Six tests beyond the bullets' literal wording**, each for a line the Interface or the ticket names: an absolute path through a symlink is resolved before the rule applies (paths 4); the relative spelling `../README.md` is never writable (paths 9); an unknown key in the file is ignored; a key from the environment is stripped of surrounding whitespace; a blank token is not exported; and a variable the user set with surrounding whitespace stays exactly as set while `Settings` normalises its own copy, which is the only way to observe `setdefault` rather than assignment, since the environment always wins inside `Settings` and the bullet's own "leaves an already-set variable alone" case is green under either.
- **Bullet 2 spells each protected directory as itself** (`docs`, `.claude`, and so on) as well as nested, so the directory entry counts as protected; likewise `is_writable("wiki")` is true. Git diffs only ever name files, so this only matters for a tool asked about a directory.
- **Public module-level names beyond the Interface**: `PROTECTED_DIRS`, `PROTECTED_FILES`, `WRITABLE_DIRS`, `WRITABLE_FILES`, `RA_SUBDIRS`, `REPO_ROOT_VARIABLE` in paths; `ENV_FILENAME`, `API_KEY_VARIABLE`, `LOGFIRE_TOKEN_VARIABLE` in settings. The rule data is the single source of truth the spec asks for; no test imports them.

Also noted: the key stays a plain `str` as the seams doc says and no code here prints it, but `repr(settings)` would show it, so a later log line that formats the whole `Settings` object is the one way to leak it (`Field(repr=False)` would close that; not added, not asked for). `REPO_ROOT` is read from `os.environ` at import, before `tests/conftest.py` strips `RA_*`, so a developer shell with `RA_REPO_ROOT` set would steer the whole test session's default root. `.env.example` already documents the five user-facing variables and needed no change. No change outside the four owned files was needed; nothing in the spec's "Kernel, Organism, Protected Paths, and the write scope" section was deviated from (six protected directories, six protected files, the five-entry allowlist).
