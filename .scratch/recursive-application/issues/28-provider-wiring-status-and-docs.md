Deviations and judgement calls for the human to confirm:

- **A `SignInError` inside `require_credentials` is wrapped, not propagated as is.** `_require_sign_in` re-raises it as `ProviderError(f"{error} for {name!r}, or point CODEX_HOME at the Sign-in")`, so the refusal stays a `ProviderError` (ticket 26's missing-file test keeps its type and now also matches `CODEX_HOME`) and `CODEX_HOME_VARIABLE` has its reader, as the orchestrator's second option suggested. - **Ticket 26's "passes once the Sign-in file exists" test is rewritten.** A `{}` file no longer counts as a Sign-in (`load_sign_in` refuses it as holding no tokens), so the test writes a Sign-in in the Codex schema and passes under a clock two hours before expiry with `ra_max_minutes=30`; it is the seams document's "passes with a token expiring in two hours" case and was green on its first run, the refusal test having landed first. - **`KernelContext` gains `model_factory: Callable[[str], Model]`, and the `evals` command builds the Judge Model through it too.** The seams document names only the Runners' closure, but `run_evals(judge_model=<str>)` would have handed a `chatgpt:` name to pydantic-evals, which calls `infer_model` itself. The three existing `evals` command tests now set `OPENROUTER_API_KEY`, because the Judge Model is built at command time (in production `build_context` has required the key just before).
