# 26: Provider factory, the OpenAI key, and the credential check

**What to build:** The Kernel module behind the agent runtime's `model_factory` seam: it parses the scheme of a model name, checks the credentials each tier needs (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`, or the ChatGPT Sign-in file), and builds the model for any pydantic-ai name through `infer_model`. Settings gain the OpenAI key, `CODEX_HOME`, and the originator; `require_api_key` moves into the module as `require_credentials`. The Policy Ceiling gains the `.codex` rule so no shell command can read the Sign-in.

Source: the spec amendment of 2026-09-06 (Providers); ADR 0011; the seams document `thoughts/shared/plans/2026-09-06-provider-seams.md`, sections `kernel/settings.py`, `kernel/providers.py`, and `kernel/policy.py`.

Deviations and judgement calls for the human to confirm:

- **`Settings.require_api_key` and its two tests are kept**, by the orchestrator's decision: `kernel/cli.py` still calls it and belongs to ticket 28, which deletes the method and the two tests when it rewires the CLI. `require_credentials` is the replacement and does not call it.
- **Settings bullet 2 became five tests, and the strip test uses the environment, not the file.** python-dotenv strips unquoted values itself, so `OPENAI_API_KEY= sk-test ` in a file gives `sk-test` with no validator at all; the proof of the validator is `monkeypatch.setenv("OPENAI_API_KEY", " sk-test ")`, mirroring the OpenRouter test. The file test keeps the seams document's two literals (`sk-test` and `Path.home() / "codex-alt"`) and went red on the `~` alone.
- **The unchecked-scheme case sets both tiers to `anthropic:claude-sonnet-5`.** The seams document's literal, `ra_model="anthropic:claude-sonnet-5"` with nothing set, would be refused for the default judge (`openrouter:openai/gpt-5.4-mini` with no OpenRouter key), not passed; setting the judge to the same unkeyed name is what makes "any other scheme is not checked here" a real test.
- **How the passing cases were made red.** "The OpenRouter key set passes" went red against an unconditional refusal written for the first case; "an `openai:` primary needs `OPENAI_API_KEY`" went red against a `KEYED_SCHEMES` holding only `openrouter`. Seven cases were green on their first run because the general implementation of the previous slice covered them, and none was made red by sabotage: the `openai:` primary with both keys, the `chatgpt` judge with the file present, the unkeyed scheme, the three further `model_factory` names (`openai:gpt-5.4`, `test`, two distinct objects), and the `docs/codex-notes.md` neighbour. Each guards a branch a narrower implementation would fail (a check on the wrong field, an unconditional `chatgpt` refusal, a check on every unkeyed scheme, a factory that only knows OpenRouter, an over-matching pattern).
- **`sign_in_path` has a direct one-line test** (`tmp_path / "auth.json"`), beyond the seams document, which reaches it only through the refusal message; ticket 28's `render_status` calls it, so its contract is pinned.
- **Interface additions:** `EXAMPLE_MODEL_NAME = "openrouter:anthropic/claude-sonnet-5"`, `SIGN_IN_FILENAME = "auth.json"`, `SIGN_IN_COMMAND = "codex login"` in `providers.py`; `OPENAI_API_KEY_VARIABLE` and `CODEX_HOME_VARIABLE` in `settings.py` as the seams document lists (nothing reads `CODEX_HOME_VARIABLE` yet). `SIGN_IN_FILENAME` is spelled here because `kernel/chatgpt.py` (ticket 27, in parallel) could not be imported; ticket 28, which wires the two modules, can make one import the other. No test imports any of these; they hold the literals.
- **The Settings field of a keyed scheme is the variable lower-cased** (`getattr(settings, variable.lower())`), which holds because pydantic-settings field names are exactly that; the alternative is a second mapping from scheme to field name. The refusal names the variable and the model name it is for (`OPENAI_API_KEY is not set for 'openai:gpt-5.4'`), never a value.
- **`model_factory` keeps `clock` and `transport` in its signature unused**, and `settings` too, as the seams document's signature for ticket 28's `chatgpt:` branch; ruff's selected rules do not flag unused arguments.
- **The `.codex` pattern mirrors `.env`'s shape**, `(?<![\w.])\.codex(?![\w.])`, so a hypothetical `.codex-backup` token would also be refused (`-` is not a word character); the refusal is in the conservative direction and the three seams-document commands and the neighbour behave as listed.
- **Docstrings:** the `settings.py` module docstring now says "the provider keys, the Sign-in directory" and the `load_settings` docstring names `OPENAI_API_KEY`.
