# 08: Wiki module and seed Wiki

**What to build:** The Wiki exists in the repo as an index, an append-only log, and the four category folders, and the Wiki module can rebuild the index from page titles and first paragraphs, append a log entry, list open questions including the Librarian's frontier proposals by capability, and produce a lint report of orphan pages and pages missing from the index. The module lives in the Organism so the system may improve it; only the Librarian writes to the Wiki at run time.

Source: spec section "Wiki" and Testing Decisions seam 8; ADR 0003; ADR 0009 (frontier proposals).

## Comments

**2026-09-05, implemented.** Red to green through the seams document's seven tracer bullets: 22 tests in `tests/organism/test_wiki.py`, importing only `Wiki`, `OpenQuestion`, `CapabilityPage`, and `LintReport`, backed by `src/recursive_application/organism/wiki.py` (Organism code, standard library only, synchronous, `pathlib`) and the seed `wiki/` (`index.md`, `log.md`, and a `.gitkeep` in each of the four category directories). The Wiki root is the only thing the class holds besides the injected clock; every path it returns is POSIX relative to that root, so the same strings serve the index links, the Sensor that reads open questions, and the Capability Inventory. The index render is one pass over `pages()`: the category is the second path segment, the title is the first `# ` heading or the file stem, the summary is the first non-empty non-heading block joined to one line and cut at 200 characters, and every category always gets a section so a reader sees the four buckets whether or not they hold anything. Because the render reads only the pages and sorts them, it is deterministic by construction, and `ensure_layout` writes exactly what `rebuild_index` would render, which is what makes the tracked seed `wiki/index.md` byte-identical to the empty render. The log is opened in append mode and never read before writing, so an earlier line cannot be lost; the stamp is `clock().astimezone(UTC)` formatted `%Y-%m-%dT%H:%M:%SZ`, and the tests fix the clock at 2026-09-05T14:15:00Z. Lint resolves markdown links itself rather than pulling in a parser: every `](target)` in the index, the log, and each page, with the target resolved against the linking file's directory and made relative to the resolved root (both sides resolved, because `tmp_path` on this machine sits under the `/var` symlink and an unresolved comparison would call every link an escape). A page is unindexed when the index does not link it and an orphan when nothing links it, a self-link excluded, which is why rebuilding the index clears both lists at once.

Deviations and judgement calls for the human to confirm:

- **Bullet 1's seed check reads the repo's `wiki/` and never writes it.** The seams document has the test compare the seed `index.md` with `rebuild_index()`'s output *for the repo's own Wiki*, but `rebuild_index` writes: a drifted seed would be silently rewritten by the failing test and pass on the next run. Instead the empty render is pinned as a literal in the test, `rebuild_index()` on a `tmp_path` Wiki is asserted equal to it, and the repo's `index_text()` is asserted equal to it too. Same coverage, no test that repairs the thing it checks.
- **The exact index layout is a judgement call.** The seams document fixes the lines, not the blank ones: `# Wiki index`, a blank line, then per category a `## ` heading, a blank line, the entry lines, a blank line, and one trailing newline. The seed `wiki/index.md` holds that byte for byte.
- **A page with no first paragraph is listed as `- [Title](path)`**, with no trailing `: `. A trailing space in markdown is a line break, and the document does not say what an empty summary renders as.
- **The 200-character cut is a plain truncation**, no ellipsis and no word boundary.
- **Category headings are derived from the directory name** (`replace("-", " ").capitalize()`, so `open-questions` reads `Open questions`) instead of a second hand-written table that could drift from `CATEGORIES`.
- **The log stamp converts to UTC before formatting.** The document says "clock() as ISO 8601 UTC" without saying what a non-UTC clock does; without the conversion a clock in another zone would be stamped with its local wall time and a `Z`. There is a test for it.
- **`append_log` only appends.** It does not create `log.md`, and it does not write the `# Wiki log` heading; `ensure_layout` is the sole creator. Appending to a Wiki that was never laid out therefore leaves a headless log.
- **Bullet 6's sequence is read as: `pages/lessons/l.md` exists and is already in the index before `pages/tasks/new.md` appears.** Taken in the document's literal order, `l.md` is created after the index was last rebuilt, so it would itself be unindexed *and* an orphan and "orphans is empty" could not hold. The tests write `l.md`, rebuild, add `new.md` (unindexed and orphan), then add the link from `l.md` (orphan cleared, still unindexed), then rebuild (both empty).
- **A stray page directly under `pages/`, outside the four categories, is reported unindexed forever.** `pages()` lists every `*.md` under `pages/` as the document says, but the index has only the four category sections, so such a page can never be linked from it. Nothing in the document covers the case; the alternative would be to hide the page from `pages()`, which seemed worse than a lint that keeps complaining.
- **The link guards for schemes and out-of-root targets carry no test**, because they are unobservable at the seam: a target with a scheme, or one resolving outside the root, can never match a page path either way. They exist so `[docs](https://example.com/x)` and `[x](../../../etc/passwd)` are dropped rather than turned into fake page references.
- **Five module constants beyond the Interface list:** `LOG_HEADING`, `INDEX_HEADING`, `SUMMARY_LIMIT`, `COMMIT_PREFIX` (`- Commit: `), and `DATASET_PREFIX` (`- Dataset: `). They are the file conventions the Librarian's prompt will have to name, so they read better as constants than as literals buried in a render. If the seams document should stay the whole public surface, they want an amendment or a leading underscore.
- **Four tests were green on their first run.** `rebuild_index` writing what it returns and rendering the same pages the same way, because bullet 1 and bullet 2's first test had already put the write and the sort in place; the second `append_log` keeping the earlier line, because bullet 4's first test was already satisfied by opening the file in append mode; `rebuild_index` leaving the lint report clean, because the index links every page it renders; and a capability page without the two proof lines reporting `None` twice, because the line reader returns `None` when no line carries the prefix. Two other tests (a second `ensure_layout` changing nothing, and a link from an indexed page clearing the orphan) were only red because the over-eager part of the previous green step was rolled back first and let the new test drive it.
