# 13: State Bundle and Capability Inventory

**What to build:** The Kernel renders, with no model call, the Capability Inventory and the State Bundle every agent receives. The inventory lists the registry's agents with their phases and tool names and descriptions, each marked proven or unproven by its dataset, the Wiki's capability pages, and each frontier capability as green over total, available only when the whole file is green. The State Bundle adds the capped repo tree with Organism paths marked editable, the eval summary as one line per dataset, the ten most severe open findings, the Wiki index, and the last three Run Records.

Deviations and judgement calls for the human to confirm:

- **The agent line names its tools but does not describe them.** The seams document's grammar is `; tools: <names joined by ", ">`, while this ticket and the spec say "tool names and descriptions". Names were kept because the Implementer alone carries seventeen tools and the inventory has to stay a short block Triage can cite; the parameter still takes `ToolDescription`s, so the descriptions are one edit away if the human wants them.
- **`render_bundle` shows the first ten findings of the list as given, in the caller's order.** The ticket says "ten findings by severity"; the ranking is `collect`'s job through `SEVERITY_RANK`, so the bundle does not re-rank and a caller that passes an unranked list gets an unranked ten.
- **A capability page missing its proof renders `- <name>: no dataset (commit unknown)`.** `CapabilityPageLike.dataset` and `.commit` are optional and the seams document spells only the complete line; printing `None` would have read as a bug in the page.
- **The bundle's empty sections carry no dash (`(none)`, `(no report)`) while the inventory's empty section is `- (none)`.** Both spellings are the seams document's own, so the difference is deliberate rather than an oversight.
- **The proven annotation resolves the report's dataset name without touching the filesystem**, `dataset_name(Path(entry.dataset), Path(EVALS_DIR.name))`, so a registry validated against a scratch checkout renders the same text. The consequence: a registry entry whose dataset is not under `evals/` would raise here, which the registry contract does not currently forbid.
- **A top-level file has no trailing slash where a directory has one** (`- README.md (editable)` against `- wiki/ (editable)`), and `is_writable` decides for both. The seams document shows the directory form only, and bullet 3's layout holds no top-level file.
- **The recursive part of the tree walks `WRITABLE_DIRS` in its declared order** (the organism package, `tests/organism`, `evals`, `wiki`), sorted inside each, rather than sorting the four directories against one another. Deterministic either way; this keeps one source of truth for the write scope.
- **`assemble_state_bundle` finds the ladders at `root / "evals" / "frontier"` and passes its own `root` to `describe_tools`**, so a scratch checkout (ticket 15) is described by its own files rather than by `REPO_ROOT`. The seams document names `frontier_ratios` and `describe_tools` without saying which directory.
- **The run line reads `1 Iterations`.** That is the seams document's literal `<n> Iterations`; a plural rule was not invented.
- **No test was green on its first run.** Bullet 1 failed with `ModuleNotFoundError` for the module, bullets 3, 4 and 5 with `ImportError` for `render_tree`, `LoopPosition` and `assemble_state_bundle`, and bullet 2 with a failed assertion (`proven by evals/triage.yaml` against the line the bullet-1 code rendered).
