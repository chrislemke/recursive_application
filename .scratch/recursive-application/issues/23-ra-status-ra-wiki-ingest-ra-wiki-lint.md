# 23: `ra status`, `ra wiki ingest`, `ra wiki lint`

**What to build:** The Operator sees the system's health and agenda at a glance and keeps the Wiki fed and consistent. `ra status` shows breaker states, open Sensor Findings, recent runs, total cost, the eval trend, the frontier ratios, and the Librarian's frontier proposals, and is well formed on a fresh runtime directory. `ra wiki ingest PATH` has the Librarian read the path and write pages through its Wiki tool, then rebuilds the index and appends the log. `ra wiki lint` prints the orphan and unindexed pages.

Source: spec section "CLI"; user stories 9, 10, 69; ADR 0009 (proposals surfaced in status).

## Comments

**2026-09-05, implemented.** Red to green through the seams document's four tracer bullets: 7 tests in `tests/kernel/test_status.py` over `src/recursive_application/kernel/status.py`, importing only `render_status`, `ingest_wiki`, and `lint_wiki`. `render_status` is a pure composition over the four things it is handed: `BreakerStore.states()` sorted by name, `sensors.collect(...)` already ranked, `RunStore.list_all()` for the last five runs and for the cost of every run ever, `ReportStore.list_all()` for the trend, `frontier_ratios(...)` for the ladders, and `wiki.list_open_questions()` filtered to the questions that carry a capability, which is what makes a Librarian proposal visible (ADR 0009). Sections are joined the way the State Bundle joins them, heading, blank line, lines, so the report reads as markdown; the empty text is `(none)` everywhere except the eval trend, which says `(no reports)` because an empty suite and a suite nobody has run are different states. The eval trend takes the datasets of the last five reports as a sorted union and, per dataset, the `passed/total` of each report that actually holds a case of it, joined with ` -> `, so a dataset added halfway through the five shows a shorter line rather than a run of `0/0`. `ingest_wiki` resolves the path to a list of documents first (`FileNotFoundError` before any model call, one file, or every `*.md` under a directory sorted), then runs the Librarian once per document through `AgentRunner.run(registry.get("librarian"), ..., bundle=assemble_state_bundle(...))` at `LoopPosition(run_id, Mode.TASK, iteration=1, iteration_limit=1, phase="learn", role="librarian")`, and only afterwards calls `rebuild_index()` and `append_log(f"Ingested {path}")` once each. `lint_wiki` is a thin rendering of `wiki.lint_report()`: two headings, sorted paths or `(none)` under each, and the code 0 only when both lists are empty. Under test the Librarian's `model_factory` returns `TestModel(call_tools=[], custom_output_text="Recorded the document.")`, so no file or shell tool ever runs against the checkout, and the Wiki that receives the rebuild and the log line lives under `tmp_path`.

Deviations and judgement calls for the human to confirm:

- **The frontier, run, and finding lines are `kernel/bundle.py`'s public `frontier_line`, `run_line`, and `finding_line`** (promoted by the review of ticket 13), so the two reports share one wording. `lint_wiki` takes a `WikiMaintainer` and the two fives are `MAX_RUNS` and `MAX_REPORTS`, both recorded in the seams document's amendments.
- **The breaker lines are sorted by name and print the `BreakerState` value** (`open`, `closed`, `half_open`). The seams document says "one line per known breaker" without an order, and insertion order would make the report depend on which agent failed first.
- **`## Total cost` sums every Run Record, not only the five shown under `## Recent runs`**, which is what the seams document says and what an Operator watching a budget wants; the two sections therefore disagree by construction once there are more than five runs.
- **Empty sections read `(none)` with no leading dash**, unlike the Capability Inventory's `- (none)`, and `lint_wiki` prints a page as a bare path on its own line for the same reason: the seams document pins the clean lint literal as `Orphans:\n(none)\nUnindexed:\n(none)\n`, so a bulleted page line would sit oddly next to an unbulleted `(none)`.
- **A directory is walked recursively** (`rglob("*.md")`) and sorted by full path. "Every `*.md` under it" reads recursive; a flat `glob` would silently skip a nested inbox.
- **The ingest prompt names the document repo-relative when it lies under `root` and absolute otherwise**, while the log entry repeats the `path` argument as given, not the per-document path, so ingesting a directory leaves one line naming the directory.
- **One State Bundle per document, reassembled before each run.** The seams document says "Each run gets the State Bundle", which allows one shared bundle; per-run is the safer reading, because a Librarian run may have written pages the next run should see. It costs a `render_tree` and a `collect` per document.
- **`render_status` reads the latest eval report twice**, once here for `frontier_ratios` and once inside `sensors.collect`, because the Sensors' seam takes a runtime directory rather than a loaded report. Cheap, but worth naming.
- **Tests green on their first run**, four of seven: the whole seeded-status test of bullet 2, the directory and missing-path cases of bullet 3, and the unlinked-page case of bullet 4. In each case the bullet's first test forced the general implementation (bullet 1 exercises all seven sections on an empty directory, so the seeded rendering was already written; bullet 3's file case already resolved documents and ran the loop; bullet 4's clean case already rendered both lists). The three later ones were checked by mutation instead: truncating the directory walk to one file, replacing the `FileNotFoundError` with an empty list, and pinning the lint code to 0 each turned exactly the expected test red.

Left for the CLI wiring step: `kernel/cli.py` builds the collaborators through `build_context()` and calls these three as module attributes, prints what they return, and maps the results to exit codes, 0 for `status`, 0 for `wiki ingest` with a `FileNotFoundError` becoming 2, and `lint_wiki`'s second element for `wiki lint`. The `run_id` `ingest_wiki` takes is the CLI's to generate. The exit-code criterion and the whole-tree "All four checks exit 0" box are therefore left unticked; ruff format, ruff check, ty check, and `pytest tests/kernel/test_status.py` all exit 0 on this module's two files.

**2026-09-05, CLI wired.** The three commands are live in `kernel/cli.py`, each built through `build_context()` and each reaching its function as a module attribute, so the tests replace both. `ra status` prints `render_status(ra_dir=..., wiki=..., frontier_dir=<root>/evals/frontier, budget_usd=settings.ra_budget_usd, breakers=...)` and exits 0. `ra wiki ingest PATH` prints `ingest_wiki(PATH, agents=..., registry=..., wiki=..., root=..., ra_dir=..., budget_usd=..., run_id=<fresh>)` and exits 0, and a `FileNotFoundError` from a missing document reaches the one error handler and exits 2 with the message on stderr. `ra wiki lint` prints `lint_wiki(wiki)`'s text and exits with its code, so a clean Wiki is 0 and a Wiki with an orphan or an unindexed page is 1. Four tests in `tests/kernel/test_cli.py` cover the seams document's bullets 5 to 7 with the three functions faked; the modules' own behaviour stays covered by `tests/kernel/test_status.py`.

Deviations and judgement calls for the human to confirm:

- **`ra status` and `ra wiki lint` need `OPENROUTER_API_KEY` even though neither reaches a model.** `build_context()` calls `settings.require_api_key()` for every command, as the CLI seam says. Without the key `uv run ra status` exits 2 naming the variable, which is the documented usage error but is arguably wrong for two commands that only read the disk. Splitting the check (only the commands that run an agent require the key) is a one-line change if the human prefers it.
- **The frontier directory is wired as `root / EVALS_DIR.name / FRONTIER_DIRNAME`**, the same expression `kernel/loop.py` uses, so the checkout's `evals/frontier/` is the one source and a scratch checkout would follow its own root.
- **`ra wiki lint` echoes the report with its trailing newline trimmed.** `lint_wiki` returns text that already ends in `\n` and `typer.echo` adds one, so an untrimmed echo would print a blank line after the report.
- **The run id `ingest_wiki` receives is `RunRecord(mode=Mode.TASK).run_id`**, generated per invocation. The Librarian's State Bundle names that run, and nothing writes a Run Record for an ingest.
