Deviations and judgement calls for the human to confirm:

- **The mapping-shaped `inputs` are block-scalar YAML strings, not YAML mappings.** `load_dataset` builds `Dataset[str, str, dict[str, Any]]` (ticket 10), so a mapping `inputs` fails validation and raises `DatasetError`; a probe confirmed it. The five affected files (`planner`, `test-writer`, `implementer`, `reviewer`, `librarian`) therefore hold `inputs: |` with the mapping inside, whose keys are the contract field names as the seams section requires. Ticket 15's `task_for` must `yaml.safe_load` those inputs. The alternative, which the human may prefer, is a one-word Kernel change, `Dataset[Any, str, dict[str, Any]]`, after which the quoting can be removed; ticket 15's own bullet 3 passes a `dict` to `task_for("reviewer", ...)`, so the two readings need reconciling either way.
- **Both `test-writer.yaml` cases target the Wiki**, where the seams section asks for one Wiki behaviour and one tools behaviour. `src/recursive_application/organism/tools.py` did not exist when these datasets were written (ticket 09 was in flight) and is still uncommitted, so a Plan against its interface could not be grounded.
- **The triage skill case carries an `LLMJudge`.** The seams section says the triage cases are judge-free except the clarification one and, two sentences later, that the skill case's `how_to_acquire` is judged to propose a new agent. The judge is kept, because that is the Specialist requirement of the ticket.
- **The clarification case asserts no Mode.** A clarification gap is not obviously a Growth trigger, and the seams section names only `kind: clarification` for it.
- **The connection case asserts `mode: growth` and `kind: connection` only.** A `needs_human` assertion was dropped: the key is rendered even when the list is empty, so it would have asserted nothing.
- **`implementer.yaml` has no judge.** Its rendering is six flags with no text to judge; the three `Contains` assertions are the whole gate.
- **`librarian.yaml` asserts on the `pages` keys, not the page text.** `Contains: pages/capabilities/` assumes the task function keys `pages` by the Wiki-relative POSIX path `Wiki.pages()` returns. The obvious alternative, asserting `- Commit: `, was rejected because `yaml.safe_dump` folds a long double-quoted string at column 80 and could split the token.
- **The headers run to three or four comment lines** rather than two, because the rendering the task function owes does not fit in two.
- **The Kernel test asserts no dataset count.** The Organism may legitimately add a Specialist dataset, so the test asserts that the ten known names are a subset of what `list_datasets` finds, not that there are exactly ten files.
- **Tests green on their first run: the two bullet-2 tests and the four bullet-3 tests.** Bullet 1 needs all seven files at once, so the datasets those bullets inspect already existed when the bullets were written. The no-model test was proved sensitive by temporarily adding `model: openrouter:x/y` to a triage judge and watching it fail, then reverting.
