# 14: Agent runtime

**What to build:** One Kernel entry point runs any registry entry: it assembles the instructions in order (Constitution, guides, the agent's prompt, the State Bundle), injects the model for the entry's tier from Settings, applies the usage limits from Settings with the higher request limit for the coding roles, runs under the entry's breaker, records Usage, and is traced. Agents in the registry never set a model themselves.

Source: spec sections "The Coding Guide and the guides mechanism" (instruction order), "Agent registry" (model injection), "Loop semantics" (budgets and breaker); the plan's agent runtime item.

**Blocked by:** 02 (Protected Path rule, write scope, and Settings), 04 (Trace Store), 05 (Circuit breaker), 12 (Organism registry), 13 (State Bundle and Capability Inventory)

## Comments

**2026-09-05, implemented.** Red to green through the seams document's six tracer bullets: 10 tests in `tests/kernel/test_runtime.py`, importing only `AgentRunner`, `AgentRunError`, and `instruction_parts`, backed by `src/recursive_application/kernel/runtime.py`. `instruction_parts(entry, bundle, root)` reads the Constitution through `load_constitution()`, each of the entry's guides and its prompt file from `root`, and appends the bundle, so the order is testable without a model. `AgentRunner.run` refuses an entry whose agent carries a model, then hands `breakers.call(entry.name, ...)` a closure that opens `logfire.span("kernel.agent_run", role=entry.name, tier=entry.tier)`, builds the model with `model_factory(name)` where the name is `ra_judge_model` for the `judge` tier and `ra_model` otherwise, and calls `entry.agent.run_sync(prompt, model=..., instructions=instruction_parts(...), usage_limits=UsageLimits(request_limit=..., cost_limit=settings.ra_budget_usd), usage=RunUsage())`. The Agent object is never touched, so the same registry entry runs twice under different settings without leaking state. Two probes settled the two facts the seams document asked to verify before relying on them: `run_sync(instructions=[...])` accepts a list, and the `RunUsage()` handed in as `usage=` is incremented in place, so after a `UsageLimitExceeded` it holds `requests=2` under `request_limit=2` — that object, converted by `_usage_of` (`cost or Decimal("0")`), is what `AgentRunError.usage` carries. The span gets `requests` and `cost_usd` on both paths and `validation_retries` (the count of `RetryPromptPart` instances in `result.all_messages()`) on the successful one. The models in the tests are a `FunctionModel` per case and, for the completed run, `TestModel(call_tools=[])`, because the entries' toolsets are already attached and the default `call_tools="all"` would drive the file and shell tools against the checkout with synthesised arguments; the request-limit tests use a `FunctionModel` that keeps asking for `read_file` with `{"path": "README.md"}`, a call the Worker and the Implementer really have, so the loop runs to the limit instead of dying on an unknown tool.

Deviations and judgement calls for the human to confirm:

- **Bullet 1 asserts the prompt part with a prefix, not the whole first line.** `first_lines[2].startswith("Phase: Decide. You produce a Plan")` rather than the planner prompt's full opening sentence: the prompts are Organism files the system may reword, and the prefix is the shortest literal that still tells the Planner's prompt from Triage's, which also opens `Phase: Decide.`.
- **`instructions=` is passed as the four-part list, but the library flattens it.** A probe showed pydantic-ai joins the parts with a blank line and `ModelRequest` carries only the joined `instructions` string (there is no parts field on the request), so the list is a call-site convenience only. Bullet 2 therefore asserts that the four marker lines occur in order inside `AgentInfo.instructions`, by index; each marker was checked to appear in exactly one of the four sources.
- **The span's `cost_usd` attribute is a `float`.** OpenTelemetry attributes have no Decimal type; `requests` and `validation_retries` are ints. `Usage.cost_usd` itself stays a `Decimal`, so nothing rounds on the Run Record side.
- **An `AgentRunError` sets only `requests` and `cost_usd` on the span.** There is no `AgentRunResult` after a limit and so no message list to count retries from; `kernel/sensors.py` already reads a missing `validation_retries` as 0.
- **Interface additions:** `CODER_ROLES = frozenset({"test_writer", "implementer"})`, `SPAN_NAME = "kernel.agent_run"`, `REQUESTS_ATTRIBUTE = "requests"`, and `COST_ATTRIBUTE = "cost_usd"`. `VALIDATION_RETRIES_ATTRIBUTE` is imported from `kernel/sensors.py` rather than re-spelled, so the writer and the reader of that key are one constant. No test imports any of the four; they hold the literals.
- **`AgentRunError(message, usage)` takes the message positionally**, sets `self.usage`, and subclasses `RuntimeError` as the seams document says; the message is pydantic-ai's own `UsageLimitExceeded` text.
- **The refusal message is duplicated from `kernel/registry.py`.** `_refuse_model` there is private, so `AgentRunner.run` spells the same sentence rather than importing a helper; the alternative is a shared public helper in the registry, which is that module's call.
- **One test beyond the six bullets:** the span reports `validation_retries == 1` after one rejected output-tool call, so the counter is proved to count rather than to be a constant zero. It was green on its first run, since the counter landed with bullet 6.
- **Two tests were green on their first run:** bullet 1's Worker case (three parts, no Coding Guide), because the general implementation of the first case already covered it, and the retry-count test above. Bullet 4's coder-limit test was made genuinely red first by temporarily reducing `_usage_limits` to the plain request limit and restoring it afterwards, so the coder branch is a real red-to-green step.
- **`cost_limit` is always set, which makes pydantic-ai warn under a test model.** `FunctionModel` and `TestModel` are unpriceable, so every run in the suite raises `CostNotFoundWarning`; a real OpenRouter model that genai-prices knows does not. The alternative, omitting the cost limit when it cannot be enforced, would drop the budget stop rule for exactly the models that are unpriceable in production too.

Also noted: the trace fixture copies `tests/kernel/test_tracing.py` (module-scoped, `LOGFIRE_TOKEN` removed, `LOGFIRE_CREDENTIALS_DIR` pointed at an empty temporary directory) because Logfire's configuration is process-global; both modules were run together in both orders and pass. Left for the orchestrator: the whole-tree run behind "All four checks exit 0", and the seam-confirmation box. The runner is only the entry point — nothing yet calls it; the Loop runner is what will pass a real State Bundle and sum the `Usage` into the Run Record.
