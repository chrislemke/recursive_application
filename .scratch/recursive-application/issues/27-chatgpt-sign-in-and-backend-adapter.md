# 27: The ChatGPT Sign-in and the backend adapter

**What to build:** `kernel/chatgpt.py`: the Sign-in read from the Codex CLI's file (never written by the Kernel), its expiry, the served-models list from the Codex cache, and `chatgpt_model`, which returns pydantic-ai's OpenAI Responses model pointed at the ChatGPT backend through an `httpx2` transport that injects the bearer and account headers, turns the library's non-streaming request into the streaming one the backend requires, answers a synthetic 401 for an expired token, and hands the completed response back as a plain JSON body. Tokens never appear in a `repr`, a message, or a span.

Source: the spec amendment of 2026-09-06 (Providers); ADR 0011; the seams document `thoughts/shared/plans/2026-09-06-provider-seams.md`, section `kernel/chatgpt.py`; the research document `thoughts/shared/research/2026-09-06-openai-provider-and-chatgpt-subscription-library-facts.md`, sections A1 to A3, B1, B2, B6, B8, B9.

## Comments

**2026-09-06, implemented.** Red to green through the seams document's seven tracer bullets: 17 tests in `tests/kernel/test_chatgpt.py`, importing only `BACKEND_URL`, `SignIn`, `SignInError`, `chatgpt_model`, `load_sign_in`, and `served_models` from the module, plus pydantic-ai's `Agent`, `models`, and `ModelHTTPError` and `httpx2`, backed by `src/recursive_application/kernel/chatgpt.py`. `load_sign_in(path)` reads the Codex schema: `auth_mode` absent or in `CHATGPT_AUTH_MODES`, `tokens.access_token`, `tokens.account_id` or the id token's `AUTH_CLAIM` `chatgpt_account_id` when that is null, `chatgpt_plan_type` from the same claim, and `last_refresh` as an aware UTC instant; every refusal is a `SignInError(SettingsError)` naming the path and `codex login`. `SignIn` is a frozen dataclass with `access_token` `repr=False`; `expires_at` decodes the access token's `exp` without verification (split on `.`, pad, base64url, `json.loads`) and `valid_for(now, minutes)` is `expires_at is None or expires_at > now + minutes`. `served_models(codex_home)` lists the `slug` of each entry under `models` in `models_cache.json`, `[]` when the file is missing or unreadable. `chatgpt_model(...)` returns `OpenAIResponsesModel(model_name, provider=OpenAIProvider(openai_client=AsyncOpenAI(base_url=BACKEND_URL, api_key=<placeholder>, max_retries=0, http_client=httpx2.AsyncClient(transport=_BackendTransport(...)))))`. The transport, per request: reads the Sign-in fresh; answers a synthetic 401 without touching the inner transport when the file cannot be loaded (`code: sign_in_unavailable`, the `SignInError`'s own message) or the token has expired at `clock()` (`code: sign_in_expired`, a message naming the path, the expiry instant, and `codex login`); otherwise sets `authorization`, `chatgpt-account-id`, `originator`, `user-agent`, and `session-id`, rewrites a non-streaming JSON body to `stream: true`, `store: false` with `accept: text/event-stream` and a recomputed `content-length`, passes a body that already streams and any non-200 response through untouched, reads the event stream with the SDK's own `SSEDecoder`, and answers 200 JSON with the `response.completed` event's `response`, or 502 JSON when the stream ends without one. Proven through `Agent(model, output_type=str).run_sync(...)` over `httpx2.MockTransport` handlers, with `ALLOW_MODEL_REQUESTS` patched true by `monkeypatch` in the eight tests that drive a mock and nowhere else: the completed run reports `output == "hello"`, `usage.requests == 1`, `input_tokens == 12`, `output_tokens == 3`, `model.model_name == "gpt-5.5"`, `model.system == "openai"`.

Deviations and judgement calls for the human to confirm:

- **The transport, not `default_headers`, sets `User-Agent` and the other identity headers.** pydantic-ai puts `User-Agent: pydantic-ai/2.40.0` into every request's `extra_headers` (`pydantic_ai/models/openai.py:2711`), and the SDK's header precedence lets per-request headers override client `default_headers` (research B1), so the seams document's `default_headers={"User-Agent": ...}` would have been overwritten on every call. All five backend headers are therefore set in one place, `_BackendTransport`, from an `identity` mapping `chatgpt_model` builds; `AsyncOpenAI` gets no `default_headers`. Bullet 4's header assertions are the ones the seams document names and they pass.
- **Bullet 7's literal is `body["type"]`, not `body["error"]["type"]`.** The SDK unwraps the `error` key before building its status error (`openai/_client.py:1603`, `data = body.get("error", body)`) and pydantic-ai hands that object on as `ModelHTTPError.body`; research B6's probe output already shows the unwrapped shape, so the seams document's `body["error"]["type"]` would have raised `KeyError`. The test asserts `body["type"] == "usage_limit_reached"`, `body["resets_at"] == 1789000000`, and that the backend's `x-codex-primary-used-percent` header survives in `error.headers`.
- **`result.usage` is a property** in pydantic-ai 2.40.0, as `kernel/runtime.py` already uses it; the seams document writes `result.usage()`.
- **Bullet 4's Agent carries `instructions="Answer briefly."`** so the body holds an `instructions` string as the bullet asserts; with no instructions pydantic-ai omits the key (research B2).
- **A `SignInError` inside the transport is also a synthetic 401**, not only an expired token. Without the mapping the exception reached pydantic-ai as `ModelAPIError("Connection error.")` and the Operator's message was lost, which the extra test's red run showed verbatim; this is the seams document's "never raises" line made concrete.
- **Three tests beyond the seven bullets:** a logged-out file without `tokens` raises `SignInError` (the Interface lists it); a Sign-in file removed between two runs answers the synthetic 401 above; a stream that ends without `response.completed` surfaces as `ModelHTTPError` with `status_code == 502`. The first two were red first. The 502 test was green on its first run, because that branch landed with bullet 4 as the natural else of the decode, and bullet 7's red runs (`assert 502 == 401`) had already shown it firing.
- **Bullet 5 was green on its first run**, because bullet 4's implementation already read the Sign-in inside `handle_async_request`. It was made red by temporarily caching the Sign-in on the transport instance (only that test failed) and the fresh read was restored, so the test is proven to detect the regression.
- **`load_sign_in` also refuses a `tokens` object without a string `access_token` or without any account** (`SignInError`), and a `last_refresh` that is absent or unparsable reads as `None` rather than raising. Both are the least handling that keeps the transport's "never raises" honest against a half-written file; neither has a dedicated test.
- **Interface additions (constants, none imported by a test):** `SIGN_IN_COMMAND = "codex login"`, `PACKAGE_NAME = "recursive-application"`, `PLACEHOLDER_API_KEY = "replaced-per-request"`. The synthetic error bodies use `type: "invalid_request_error"` with the codes `sign_in_unavailable`, `sign_in_expired`, and `incomplete_stream`.
- **The 502 body carries no event data.** The probe's adapter turned `response.failed` and `error` events into a 502 holding the event; here any stream without `response.completed` is one 502 whose message names the missing event, so no backend text is formatted into a Kernel-made body. If the failed event's message matters for diagnosis, that is one branch in `_completed_response`.
- **`transport=None` builds `httpx2.AsyncHTTPTransport()`** with httpx2's defaults; timeouts stay the SDK's (600 s read, 5 s connect), which apply to the whole consumed stream (research B8, note 3).
- **One warning per `run_sync` test:** pydantic-graph's `asyncio.get_event_loop()` `DeprecationWarning` ("There is no current event loop"), also raised by `tests/kernel/test_runtime.py`; a library matter, not this module's.
- **No research fact proved wrong.** B6 was right about the unwrapped body; the inconsistency was in the seams document's bullet 7 literal.

Also noted: `openai._streaming.SSEDecoder` is a private import, as the seams document's Internal section chose; ruff's selected rules do not flag it.
